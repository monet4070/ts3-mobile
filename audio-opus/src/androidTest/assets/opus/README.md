# Synthetic Opus compatibility corpus

Generated by `tools/check-opus-compat.py --write-fixtures` using the official
1.3.1 and 1.6.1 source releases pinned in `tools/opus-compat.lock.json`.
All audio is mathematical PCM (8,000 peak, 1,000 Hz left/mono, 2,000 Hz right,
or exact digital silence). No recordings, personal data or server traffic.
`sha256.json` checks each corpus before Android tests decode it.

Both corpora use 48 kHz, 64 kbps constrained VBR, complexity 10, fullband ceiling
and 16-bit input. Voice uses VOIP / voice signal; music uses AUDIO / music signal.
Stereo channels are forced only in these test encoders so left/right contributions
can be verified after the production decoder's mono downmix.
DTX is enabled only for the silent test scenario; `OPUS_GET_IN_DTX` confirms 91
of its 100 encoder frames are in DTX. DTX packets remain nonempty and are never
treated as transport end markers. Production encoding retains DTX disabled.

The 120 ms test packet is six copies of one valid 20 ms encoded frame combined by
the Opus repacketizer. It tests legal duration/framing, not natural 120 ms music.
Its payload may exceed 1,275 bytes because it contains multiple Opus frames.
There are 12 scenarios / 650 packets / 906,000 decoded samples per encoder version.
Modes cover hybrid voice and CELT music, mono/stereo and transitions in one decoder.

Host tools build 1.3.1 with the recorded `legacy-build.patch` (version discovery
and a missing optional CMake helper only); no codec algorithm source is changed.
The old CMake implementation uses scalar fallback on Apple ARM64. Therefore
bit-identical packet generation across compiler/architecture versions is not
required; stable checked-in corpora are the Android before/after comparison.
The host verifier checks generated packets and checked-in corpus hashes.
Neither these fixtures nor synthetic tests prove real-server end-marker behavior,
perceived quality, stereo playback preservation or device CPU/power performance.

`fec-1.6.1.json` is a separate 160-frame pair with and without in-band redundancy,
generated by `fec_fixture` from `src/test/cpp/opus-compat/fec_fixture.cpp` using the
same pinned 1.6.1 host build. It uses 48 kHz mono / 20 ms / VOIP, a varying harmonic
signal, 24 kbps constrained VBR, wideband ceiling, and test-only FEC=2 / expected
loss=30 for the enabled case. The control sets both to zero. Metadata from
`opus_packet_has_lbrr` confirms 131 redundant packets and zero in the control.
`fec-sha256.json` validates this independent asset; it does not change the original
two-version corpus or production encoder settings.

Reproduce after the host compatibility script has verified/extracted sources:

```sh
cmake --build build/opus-compat/host-1.6.1 --target fec_fixture
build/opus-compat/host-1.6.1/fec_fixture > build/fec-1.6.1.json
```

The JSON can be pretty-printed for review and its SHA-256 compared with the stored
fixture. Floating-point compiler differences may change encoded bytes; native
tests always replay the same stored packets and compare FEC against PLC using
the no-loss decode of those packets as the reference.
