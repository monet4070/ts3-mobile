# A4a Opus 1.6.1 升级执行记录

## 修改前评估与范围

现有音频经 NativeOpusEncoder / NativeOpusDecoder 接入单个 ts3opus_jni，
由 audio-opus 的 Prefab 依赖提供 libopus 1.3.1。协议与播放调度不依赖具体 codec 版本。
本轮改为官方源码包的固定 SHA-256 / CMake 静态构建，保留 public API、48 kHz / mono /
20 ms / 64 kbps、VOIP、受限 VBR、complexity 10、VOICE signal、fullband 上限和 16-bit 输入。
不同时调整抖动策略、FEC、DTX 开关、APM 默认值或用户配置。

相关 JNI 文件约 210 行，不需要扩大生命周期职责；来源配置单独放入 opus-source.cmake，
交叉兼容 fixture 与 host 工具留在独立测试目录。工作区已有改动全部保留，不提交或建分支。
风险为 ABI/符号、源码构建选项、新旧包与单/双声道兼容、Release 打包和第三方许可。

- 官方归档 `https://downloads.xiph.org/releases/opus/opus-1.6.1.tar.gz`。
- 发布页 SHA-256 与实际下载一致：`6ffcb593207be92584df15b32466ed64bbec99109f007c82205f0194572411a1`。
- upstream tag `v1.6.1`，tag object `a5d6c1b6f4e582df97390f9ac5c6e7c51cbffffe`，
  commit `22244de5a79bd1d6d623c32e72bf1954b56235be`；构建以完整发布归档 hash 为准。
- 对照归档 1.3.1 SHA-256：`65b58e1e25b2a114157014736a3d9dfeaad8d41be1c8179866f144a2fb44ff9d`。

host 工具也执行 1.3.1 / 1.6.1 编码器与解码器的四向交叉验证；不在生产 APK 同时装两套 Opus。

## 实现与兼容边界

2026-10-24：A4a 源码升级与离线兼容验证完成，生产构建采用 1.6.1。
默认仍只有一个 codec；未启用神经增强、DRED、OSCE、FEC 或新的发送 DTX 策略。

- 生产：新增 opus-source.cmake / opus-options.cmake；CMake FetchContent 从官方地址或记录的镜像
  下载并校验，静态 PIC 链接到 ts3opus_jni。JNI 只调整头文件入口并增加内部版本查询，编码控制未变。
  NativeOpusInfo 用于核对实际装载版本；没有新增用户可见 API 或持久设置。
- 测试：新增独立 host C++ 编码/解码工具、Python 四向验证器、两版本合成 corpus、
  Android 元数据/样本/声道/DTX/模式切换/异常包/生命周期测试，以及实际 minified APK codec probe。
- 文档：同步中英文 README、ARCHITECTURE、CONTRIBUTING、CHANGELOG、第三方声明、ADR-0018、方案及本记录。
- 配置/依赖：移除 version catalog 中旧 Opus 坐标和 audio-opus Prefab 配置。
  用 `--write-locks` 执行依赖解析后审查差异，移除无关 metadata 解析噪声；最终 app 锁仅删除旧 Opus 条目，
  audio-opus 锁仅删除旧 Opus 与 Prefab CLI 两条，其他锁定版本保持不变。
  CI 增加 host 兼容检查和 Release codec smoke；许可证资产更新为与 upstream COPYING 完全一致的内容。

原生使用 float、hardening，明确关闭固定点、fast-math、custom modes、deep PLC、DRED 和 OSCE。
保留 upstream CPU 检测与可用 SIMD，codec 在 Debug 和 Release 均单独开启 `-O3`，
避免 Debug 的无优化编译拖慢实时音频。NDK、CMake、minSdk 和共享 libc++ 策略保持原设置。
`--exclude-libs,ALL` 隐藏静态 codec/RNNoise 的动态符号，JNI 函数继续导出；不在 APK 内混装旧版库。

## Fixture 与新旧交叉验证

可重放的素材位于 [Android fixture 目录](../../audio-opus/src/androidTest/assets/opus/README.md)。
音频只由公式产生：48 kHz、峰值 8,000、左/mono 1,000 Hz、右 2,000 Hz，或数字零。
使用受限 VBR / 64 kbps / complexity 10 / fullband 上限 / 16-bit 输入。
VOICE 为 VOIP + voice signal，MUSIC 为 AUDIO + music signal；只有测试编码器强制双声道或开启 DTX。

每个版本 12 个场景、650 包、906,000 个单声道解码样本，两个版本共 1,300 包。
覆盖 2.5/5/10/20/40/60/120 ms、mono voice/music、stereo 双侧/仅左/仅右、hybrid/CELT 模式切换。
120 ms 包由 repacketizer 合并六个同配置 20 ms frame，部分包大于 1,275 字节；
这是合法多帧包上限测试，不改变现有 20 ms 生产编码器的输出容量。

两份 corpus 分别用官方 1.3.1 / 1.6.1 编码，hash 为：

- 1.3.1：`445b5894618044bd89972bd7a1ed6c3cd824d33a455b491869354bb408ee1933`
- 1.6.1：`c9dd19c3920429d5059d426644eaaf731e43e62d018f2e8e93089ac5195dcb18`

Android 每次先核对 sha256.json，再将同一批包送入实际生产 JNI；不是随意构造的 transport payload。
旧 Prefab 1.3.1 的 5 个用例和升级后 1.6.1 的全部兼容用例均通过；版本查询分别记录了
`libopus 1.3.1` / `libopus 1.6.1`，未用源码声明代替实际装载结果。

主机的两编码器 × 两解码器 × 12 场景，共 48 组通过。每组检查解码包数/样本数、
stereo bitstream、单声道下混后的左右 tone 幅值和低能量 DTX，并拒绝已知损坏包。
左右独立贡献阈值为幅值 >1,500，单侧静音时非目标 tone <500（Android）。
双声道按 mono 接收，未新增立体声播放或改变 OPUS_MUSIC 的支持策略。

DTX 场景中 `OPUS_GET_IN_DTX` 确认 100 帧里有 91 帧进入 DTX，真实 DTX 包均非空。
接收管线逐包解码并准确推进 100 × 960 样本，无 PLC、无提前结束；transport 空 payload 仍不进入 decoder。
原固定 ts3j 的 end-marker 互通问题不由 codec DTX fixture 代替，仍待双端/真实协议验证。

1.3.1 的发行包 CMake 缺少 opus_buildtype.cmake，并会误用父仓库 git tag；
测试构建应用记录的 [legacy-build.patch](../../audio-opus/src/test/cpp/opus-compat/legacy-build.patch)，
只修正包版本和缺失的可选构建 helper。未修改 1.3.1/1.6.1 算法源码。
host 为 Apple clang 21.0.0 / ARM64，旧版 CMake 使用 scalar/rounding fallback，
因此不要求跨编译器、CPU 的编码字节完全一致；Android 前后对照始终使用相同已存档 corpus。

## 构建复现

```sh
python3 tools/check-opus-compat.py --sdk "$ANDROID_HOME"
./gradlew --no-daemon --max-workers=2 quality :ts3-protocol:test :audio-opus:testDebugUnitTest :audio-opus:lintDebug :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleRelease
./gradlew :audio-opus:connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=io.github.ts3mobile.audio.opus.NativeOpusCompatibilityTest,io.github.ts3mobile.audio.opus.NativeOpusCodecTest
python3 tools/check-release-codec.py --device emulator-5554 --sdk "$ANDROID_HOME"
```

首次 CMake 构建下载官方源码，之后复用各构建目录缓存。网络或离线场景可传
`-PopusSourceArchive=/absolute/path/opus-1.6.1.tar.gz`，只替换文件位置，hash 仍强制一致。
本轮可选 APM 回归实际使用了本地归档并完成四 ABI 构建，另一个损坏本地归档配置被 SHA-256 校验拒绝。
源码修改/版本升级须调整锁与配置并重新构建，不修改 `.cxx` 解包目录；回退为重建旧版本，不吞异常动态切库。

环境沿用 Corretto JDK 17.0.21 / Gradle 8.9 / AGP 8.7.0 / Kotlin 2.0.0 /
Android SDK 35 / NDK 27.0.12077973 / CMake 3.22.1，Android 仪器运行于 API 35 ARM64 AVD。
编译与打包包含 arm64-v8a、armeabi-v7a、x86、x86_64；其余三种 ABI 没有本机运行时证据。

| 原生/打包核验 | 四 ABI 都为 1.6.1，单一 codec，静态 Opus 符号隐藏，JNI 入口保留；LOAD 段至少 16 KiB |

| 隐私 / 许可证 | 隐私扫描通过；许可证字节与官方 COPYING 完全一致 |

Release codec probe 从实际 APK 提取对应 ABI 原生库，用独立编译的 Java/dex probe 和 PathClassLoader
调用 APK 内的 native 接口；不重编 APK、不影响 R8 可达性、不安装应用或启动服务。
全部验证只用合成音频、fake 或本地模拟器，没有采集实体麦克风、真人语音或连接真实 TS3 服务器。

本轮遇到 CMake 自带 curl 的 HTTP/2 下载错误，增加官方镜像后默认远程构建成功。
依赖报告解析曾产生无关 metadata 锁噪声，审查后只保留三条必要依赖删除，STRICT 构建通过。
长期运行 Gradle daemon 的 JIT code cache 用尽曾使 R8 极慢；取消该次构建后，一次性进程 46 秒完成全部门禁。
未修改 gradle.properties。保留既有 R8 规则和 NameServiceDescriptor 提示，未处理无关警告。

### 包体

新 Release APK 为 15,383,803 字节；A3 旧包为 14,877,171 字节，四 ABI 合包净增 506,632 字节（约 0.48 MiB）。
该差值包含新版 codec 和本轮 JNI/打包变化，不是单 ABI 算法大小或音质提升证据。
APK 中 ts3opus_jni 包含 Opus 与原有 RNNoise，Release strip 后：

| ABI | ts3opus_jni 字节数 |
| --- | ---: |
| arm64-v8a | 1,867,920 |
| armeabi-v7a | 1,734,796 |
| x86 | 1,991,724 |
| x86_64 | 1,965,680 |

默认 Debug/Release 都不包含实验 APM 原生库，也没有独立旧 libopus.so。
原 A0 指纹保留；40 项中有 6 项是本轮/前轮有意变更的 catalog、两份锁、audio-opus Gradle/CMake 和 Opus JNI，
其余 34 项仍匹配，全部 RNNoise 源码/模型未变。
本地 `build/audio-a4a-2026-10-24/` 保存前后 Android XML、host-compat、final-gates、APM、
Release codec/identity、packaging/ELF hashes、zipalign、archive rejection 和来源/fixture hashes 等证据。
