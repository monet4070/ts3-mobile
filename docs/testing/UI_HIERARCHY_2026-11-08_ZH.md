# UI 层级、门控调节与聊天气泡

日期：2026-11-08。状态：实现及最终本地回归完成，后续 Xiaomi 14 补验见文末；未公开发布。

## 修改前理解与范围

依据用户的实机截图与反馈，调整 Compose 展示层：搜索结果的名称／归属／操作，
同一刻度上的实时电平与门限，以及聊天左右气泡、居中系统提示和输入区。
统一标题字重与分组间距，保持现有暖色深浅主题。
已读架构、入口、聊天模型、搜索策略、麦克风设置／电平链路与相关独立测试。
不修改协议、音频处理、发送资格、门控参数范围、身份或偏好格式。

现有 MainScreen 超过约 300 行，本轮不改动；入口已能容纳新的子组件。
相关生产子组件均低于约 300 行，分开保留搜索行、调音分组、测量显示和消息排版职责。
主要风险是大字／键盘下操作不可见、气泡宽度影响长文阅读、门限和实时条刻度不一致，
以及界面调整误改变按住释放／发送结果语义。通过真实 Compose 布局、既有入口回归和新回归约束。

## 展示调整

- 对话框使用无衬线标题，分开标题、可滚动内容和底部操作，沿用已有深浅主题。
- 搜索按频道／用户分组显示结果数；每行使用图标、加重名称、次要频道／密码提示和右侧加入按钮。
  当前频道用明确的状态图标表示。加入用户频道仍走原会话／身份校验及密码处理。
- 麦克风设置按门控、输入音量、声音处理分组。实时声条绘制在门限 Slider 的实际轨道中，
  共享 −60 至 −15 dBFS 刻度并遵循 RTL 方向；范围外只钳制条长，数值仍显示实际 RMS。
  门限数值放在轨道下方，颜色对应滑块。采集／发送状态、正常 PTT 警告和停止入口保留。
  保存失败优先出现在顶部，成功状态与重置放在设置末尾。
- 聊天使用左侧接收／右侧发送的限宽气泡，保留发件人、时间、完整正文、截断提示和真实发送结果；
  频道切换提示居中。输入栏压缩常态说明并增强发送按钮，错误／不可发送提示仍显示。
  长按复制只复制正文，原草稿、未读、阅读位置和发送资格不变。

## 回归发现与修正

首次组合套件共 220 项：214 通过、4 失败、2 个原外部夹具跳过，原日志／XML 保留。
两项聊天导航精确偏移断言发现新增列表内容边距影响原锚点与偏移的对应关系。
去掉新增内容边距，继续使用每条气泡自身的间距，未改原导航保存逻辑或放宽偏移容差。
另两项调音回归发现从下方处理区滚回 Slider 后，上方门限数值可能在视口外；
将数值放到实际轨道下方，保留原操作和可见性断言后补验。

独立搜索测试最初没有区分输入框、弹窗结果和背后同名频道；限定结果行后修正测试定位。
格式检查发现的超长行已拆行，未关闭规则。早期通过只对应早期输入，最终结果单列如下。

## Xiaomi 14 后续实机补验

用户连接手机后，使用同一冻结 Debug APK 在 Xiaomi 14（23127PN0CC）／Android16／API36、
arm64-v8a／4 KiB、1200×2670／density480 上补验。系统字体原值为 0.9，未修改系统字体或输入法设置。
原主包 SHA256 为 R4 的 `6bd31f…8686`；确认开发证书相同后 `adb install -r`，
安装后拉回实际 APK 的 SHA256 与上述最终 UI 候选完全相同。
首次启动前，原身份、表单、历史、外观和收藏共五个 DataStore 文件的摘要全部保持。

实际应用入口检查：

- 未连接时打开麦克风设置，触摸门限从 −40 调到 −31 dBFS，并恢复 −40；
  门限值和声条同屏，麦克风始终显示未开启。第一次拖动恢复因坐标落点为 −39，
  随后精确点按恢复 −40，没有改动产品参数范围或生产实现。
- 滚动查看输入音量和声音处理，开关、保存完成状态和底部关闭按钮可达。
- 使用原保存表单成功连接，搜索真实频道／用户，名称、所属频道、右侧加入或当前频道状态分层显示；
  实际列表可滚动找到用户指定成员。途中手机前台被切到其他应用，首次搜索输入不计为完成，
  返回主应用后继续；没有将这次交互中断写为产品缺陷。
- 打开真实聊天输入框，OEM 输入法展开后，输入、发送、按住说话和停止麦克风操作仍位于键盘上方。
  未发送真实文字或戳一戳，电脑未播音，本轮未启动真实采集。
- 真实会话已主动断开，诊断收到服务器退出确认，再开始独立合成 UI 测试。

手机已有 `io.github.ts3mobile.app.test` 使用不同签名，初次覆盖安装测试包被系统拒绝，
随后启动旧 runner 也被拒绝；这两次不计为 UI 测试通过。
没有卸载旧测试包或主应用。使用忽略目录的 Gradle init 脚本仅为本轮测试指定独立
`io.github.ts3mobile.app.uitest20261108`，仍以原主应用为 instrumentation target；
主 APK 摘要保持不变，测试签名与主包一致。该包用于 fake 会话和合成电平，不连接真实服务器。

独立测试包首次启动后，前台再次离开主应用，首项布局测试一直等待可见界面；
代理在已确认真实会话断开后停止该仪器进程，runner 随之输出 `Process crashed`。
这是本次主动中止的结果，不记为产品自行崩溃或测试通过；原日志保留。
用户随后确认暂不操作手机，继续运行。整批运行仍在 Activity 连续启动／收尾阶段等待，
其中首四项成功，后续没有结束，不能全部归因于用户操作。
两类独立批次也出现等待并触发有界终止，本轮未定位批处理等待的根因。
没有为通过测试修改产品代码、原断言或测试等待逻辑；改为每项独立启动 runner，
每项保持原测试实现、主包 SHA256 和数据，使用同一测试 APK，外部 40 秒超时限制。
