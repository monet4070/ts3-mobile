# 脱离 USB 的音频诊断

日期：2026-11-09。状态：实现、离线验证及 Xiaomi 14 实机留证流程验收完成，兼容签名候选包已保留数据覆盖安装；实际弱网断续尚未复现。

## 架构、范围、风险与计划

问题：现有 report/v2 只有会话入口计数和 128 条连接/电源事件。
voiceFramesDropped 不是网络丢包或播放丢帧数；底层 ReceiveStats 在播放结束时仅输出日志，
进程被清理或系统缓冲覆盖后无法取回。用户要求在实际移动网络环境离线留证。

音频模块提供数值与固定枚举的只读统计快照，接入现有计数，补充到包间隔、队列水位、
worker 间隔、输出写入与路由/焦点事件。应用层独立控制器每 5 秒采样，进程级仓库在 IO
保存有界记录，避免旧服务的晚到收尾覆盖新服务数据。复制报告保留原有 session/history，
新增带独立 schema 的 audio 字段；不存音频、包内容、说话人/设备名、地址、密码或身份。

正常停止追加末次快照；强杀只能恢复最近一次成功落盘，允许末尾约一个采样周期丢失，
调度/存储失败可能使窗口更长，报告保留实际采样与落盘时间及失败计数，不宣称零损失。
到包间隔包含自然静默，序列跳过/PLC/FEC 与网络丢包并不等价；不能仅凭一个指标定因。

大文件评估：OpusAudioPlayer、TeamSpeakService、MainActivity/MainScreen 已接近或超过 300 行。
本轮只加入观测/导出接线，统计采样、落盘和格式化均在新协作者内；不搬动连接所有权、
音频生命周期或 UI 状态。后续若继续扩展播放器，先独立迁移焦点/输出准备，再拆分生命周期；
若继续增加诊断 UI，优先使用独立屏幕，逐项保留现有导航和后台会话测试。

测试计划：独立 JVM 覆盖计数与窗口峰值、退序/静默/重缓冲语义、轮转/跨实例恢复、异常输入、
落盘失败、结束/旧服务竞态与隐私；Android 覆盖采样接线、退出后导出及标记操作。
运行格式/静态检查、JVM、离线 Android 测试和 Debug/Release 构建，不用真实服务器作自动化夹具。


## 完成的能力与使用方式

1. 在实际出现断续的网络环境使用，不需要 USB 或电脑。
2. “更多选项 → 诊断”顶部可“标记刚才断音”，标记使用手机当前时间；也可以手动记下断音时间。
3. 正常结束测试后断开连接，再“保存文件”导出 JSON；复制入口继续可用，超大报告会提示使用文件。
4. 被系统清理后，重新打开应用即可导出已落盘记录，不需要重新连接服务器。

每 5 秒目标采样一次，保留最近 3 次音频播放代次，每次最多 120 条采样，正常约 10 分钟。
首尾采样及停止请求可能缩短实际覆盖时长，以每条 timeMs/windowMs 为准。
每代次最多 64 条事件，其中 16 条独立保留给断音标记、48 条给路由/焦点等事件，
频繁输出重建不能立即挤掉用户标记。最后一条采样的累计计数仍覆盖整个播放代次。
历史日志上限 1 MiB，平时追加小检查点，达到边界才原子压缩，避免每 5 秒重写整个历史。

报告保留原有 session/history，新增 audio，schema 为 ts3-mobile-audio/v1。
counterKeys/peakKeys 标注数值数组各列，避免重复字段名导致 Android 剪贴板事务过大。
记录包括：

- 提交/准入、过期、无效、重复、迟到、预算重置、序列跳过、PLC/FEC、重缓冲；
- 输入队列峰值与清空、PCM 溢出/重置丢弃、输入/混音等待峰值；
- 到包间隔、超过 60 ms 的间隔数，worker 间隔及超过 30 ms 的次数；
- 输出建立、写入样本、零写入、写入耗时、欠载、恢复、排空超时及观测读取失败；
- 全局/参与者失效、实际路由粗类型、所选路由、切换/保护静音与固定路由错误；
- 网络粗类型/代次、连接/播放状态和 CPU 保活状态，以及焦点和手动时间标记。

到包间隔包含发送方自然静默；PLC/FEC、序列跳过或 PCM 丢弃均不能直接当 UDP 丢包率。
成功写入也不能证明可闻交付。当前能力可帮助缩小发送端/接收排队/解码/输出/路由的范围，
不能仅凭某一个计数确认根因。本轮没有修复或声称已解决移动网络断续。

## 生命周期与文件导出回归

音频线程只更新内存原子计数或固定事件；快照、格式化和落盘在后台执行。
唯一应用级仓库跨服务实例存在，旧服务的晚到结束只封存自己的代次，不覆盖新会话。
正常 worker 结束封存不可变末次快照，定时采样先于回调读到它时也保留最后一段峰值。
强杀恢复会标 PREVIOUS_RUN_INTERRUPTED，记录的结束时间是最后观测时间，不假称精确退出时间。
采样调度、尚未写入或存储失败可能让缺失尾部超过一个周期；报告含实际落盘时间和失败数。

Release 的真实系统选择器验证曾发现：Activity.onStop 会解绑服务，返回时再从 Binder
生成报告可得到空文件。已改为打开选择器前准备脱敏快照，在 noBackupFilesDir 最多保留
一份 512,000 字节的待导出文件，成功或取消后清理，进程重建后回调不依赖服务绑定。
中断流程可能保留它到下次导出覆盖；不持久化 URI 授权。文件反映点击保存时的记录。

## Xiaomi 14 实机留证验收

2026-11-09 在 Android 16 / API 36 的 Xiaomi 14 上，以原签名 Release 候选包覆盖安装成功。
安装后二进制 SHA-256 与候选包一致，应用 UID 保留；安装前后记忆的 4 个连接表单字段全部一致。
没有卸载或清除应用数据，实际测试使用已有服务器的 chat 频道。

收听会话持续约 12 分 39 秒，保留末尾 120 条采样；采样期间网络粗类型均为 CELLULAR，
活跃采样的实际输出路由均为 BLUETOOTH。用户曾确认“能听到，暂时流畅”，
这不代表整段会话均有人工持续监听，也不代表已复现或修复此前的弱网断续。

执行一次“标记刚才断音”，仅验证功能，不代表真实听到断音；私有操作记录明确标注其用途。
随后正常断开，重新启动应用，在未连接服务器的状态通过系统文件选择器导出 JSON，确认：

- 真实手机档案仍含 1 个会话、120 条采样和 1 条 USER_MARK。
- 会话结束时间与末次采样时间一致，末次 active 为 false，累计提交和输出采样数均大于 0。
- failedWrites、invalidRecords、DIAGNOSTIC_READ_FAILURES 均为 0，正常停止的接收统计日志已捕获。
- 输出失败和排空超时为 0；PLC、欠载等计数不能直接解释为网络丢包或可闻断音。

本次记录证明真实设备的采样、落盘、标记、正常结束、重启恢复和离线文件导出流程可用。
USB 本次保持连接；脱离 USB 的真实弱网听感、锁屏长时及系统清理行为仍需现场验证。
验收后返回已保存服务器的 chat 频道，保持按住说话未按下。
