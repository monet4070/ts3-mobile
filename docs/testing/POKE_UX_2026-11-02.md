# Poke interaction and receive alerts — 2026-11-02

## Architecture, scope and plan

The channel roster and Users menu share captured `PokeRecipient` validation.
`ConnectedContent` currently forces the Chat tab after submission and
`ChatStore.claimPoke` independently changes the active conversation. Remove both
implicit navigation changes; retain private poke history and report completed
send outcomes through a short snackbar.

Use a project-native 24 × 24 outline hand/tap SVG and matching Android vector
for the channel member action. Keep the existing 48 dp touch target and a
localized member-specific accessibility label. The dialog should contain only
the recipient, optional reason and actions in its normal state. Show validation
and send errors only when relevant.

The receive adapter marks absent `msg` as missing text, although a poke's reason
is optional; the store then discards it. Treat an omitted reason as empty and
test a parsed `notifyclientpoke` through the pinned ts3j event factory. Existing
generation, malformed-sender and self-event checks remain in force.

The service currently provides no Android poke alert. Add an isolated observer
of immutable chat state and app visibility: foreground receives use the existing
dialog; background/locked receives post one generic notification on a dedicated
channel. Notification content/intent must contain no server, sender or reason;
tapping opens the app's pending dialog. Clear stale notifications on foreground,
dismissal, session end and service destruction, and do not replay old notices.
Use the existing notification permission and respect system notification policy.

Remove channel-detail UI, callbacks, app state/controller/binder plumbing and
obsolete app tests/resources. Channel expansion/join, discovery and presence
remain available. Preserve the protocol's public read-only channel-info port
for compatibility; it is no longer exposed by the app.

## Decomposition and risks

`ChatStore.kt` (310 lines) will receive only the narrow selection fix; extract
poke-specific storage later if this responsibility expands. `TeamSpeakService`
(579 lines) will only wire a dedicated alert collaborator; new notification and
visibility/deduplication behavior belongs in separate files. `MainActivity`
(304 lines) only loses obsolete channel-info callbacks. The 625-line protocol
facade is unchanged; the receive fix belongs in the small `PokeMessage` mapper.
Removing channel-info test plumbing brings `UiFixture` below 300 lines.

Main risks: optional reason handling, stale-session alerts, duplicate foreground
and background prompts, hidden send failures after removing automatic navigation,
and narrow/large-text icon controls. Add focused protocol, JVM and Android
regressions, then verify the existing separate debug installation on the phone.
No identity, bookmark, audio, connection or dependency format changes are needed.
