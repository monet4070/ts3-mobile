# A3 APM 对照原型执行记录

## 修改前评估与范围

A2 已具备限幅后的最终混音，PlaybackTimeline 仍是实际部分写入计数的唯一来源。
当前没有 render reference、采集/播放时间映射或 APM，不能仅接入 AEC 开关就宣称有效。
本轮先实现会话持有的有界参考组帧、同单调时钟的时延估计和实验 DSP worker，
以固定来源的 standalone APM 原生构建验证合成回声、双讲与断层；默认路径保持系统 AEC / RNNoise。

相关 PlaybackTimeline 小于 300 行；不扩大服务职责。OpusMicrophoneCapture 已接近/超过
300 行，本轮不向其中加入实验控制，后续真机接入须先提取 AudioRecord I/O 与时间戳适配器。
APM 的处理状态、参考历史和失败均属于单个实验会话，不引入全局音频状态。

## 来源与构建边界

候选为 freedesktop 的 standalone `webrtc-audio-processing` 1.3 发布归档，包含 AEC3，
并固定 Abseil 20230125.1、Meson wrap patch 和 Meson 1.5.2 wheel 的 SHA-256。
完整 URL/哈希在 [构建锁文件](../../tools/apm-experiment.lock.json)，
[构建脚本](../../tools/build-apm-experiment.py) 只下载校验过的归档，禁止 Meson 自行下载。
采用独立 APM 模块而非完整通话 SDK；NDK 27.0.12077973、API 26、C++17、PIC 静态库。
Meson 产物经可选 CMake/JNI 实验库链接。默认构建不下载、不编入、不启用该库。
上游 1.3 是本原型固定的旧快照，不等于当前 WebRTC；进入产品前仍需版本维护与安全评估。
构建产物旁保留 WebRTC、PATENTS、Abseil 及 FFT/VAD 第三方声明，未修改上游算法源码。

## 实现与兼容边界

2026-10-24：A3 离线原型实现与合成验证通过；真机采集接入和声学验收尚未完成。

- 生产代码：新增 `PlaybackReferenceSink`、`RenderReferenceBuffer`、`AudioSampleClock`、
  `AndroidAudioClocks`、`ApmDelayEstimator`、`ApmProcessor`、`NativeApmProcessor`、
  `ApmExperimentWorker`、`ApmCapturePipeline` 及独立 JNI 包装。
  调整 PlaybackOutput/AndroidPlaybackOutput/PlaybackTimeline 的可选参考与时间戳端口，
  为 OpusAudioPlayer 增加 internal 注入构造，原 public 单参数构造继续使用 null sink。
  MicrophoneFrameProcessor 增加 float 输入，沿用同一增益/门控/限幅逻辑，原 short 入口没有额外 float 拷贝。
- 测试：新增四个 JVM 测试文件与 NativeApmExperimentTest，扩充 fake 输出时间戳；
  生产源码无测试专用分支、真实服务器或录音 fixture。
- 文档：同步中英文 README、ARCHITECTURE、CONTRIBUTING、CHANGELOG、第三方声明、ADR-0018、方案及本记录。
- 配置/依赖：新增显式 `apmExperimentRoot` Gradle 参数、可选 CMake 片段、归档锁和构建脚本。
  未改现有 Maven/Gradle 锁、RNNoise 来源/模型、Opus 参数、权限、UI 设置格式或音源默认值。

APM 在原生层处理 48 kHz / mono / 480 样本 float。AEC3 与 APM NS 由构造参数表达意图；
AGC1、AGC2、自适应数字增益、前置放大及高通显式关闭。本轮 AEC3 也不强制开启高通。
实验处理中不调用 RNNoise，回退由调用方显式恢复已验证的基线；基线恢复失败向上传播，
不自动换成无处理，也不启动、重启 AudioRecord。基线资源仍由提供该回调的会话持有并释放。

路由策略要求已校准音源与已验证禁用的可控系统效果。Bluetooth 和未知路由均拒绝进入实验。
运行中策略失效会退出实验，恢复允许策略不会自动重启实验。NS/AEC 意图变化要求显式重建，
音量/门控/修订变化则清除旧组帧、起声与 native 状态，保留 A2 的增益斜坡语义。

## 参考与时钟实现

- 可选参考位于实际成功写入后，输入是每人增益、混音、软件限幅后的 PCM；未写入、失败或丢弃的数据不进入参考。
- 跨部分写入组成 480 样本块，携带输出代次、起始样本、480 样本长度、接受时间及估计呈现时间。
  不为不足 480 的参考尾块补造样本；输出结束/flush 会清空未完成块。
- 参考环上限 50 块，采集未订阅时不积累；单个 DSP tick 最多取 5 块。
  剩余积压、超过 500 ms、样本断层或代次变化会丢弃历史并重置；输出线程不调用或等待 AEC 运算。
- AudioTrack 时间戳先换算到本次输出原点，覆盖 32 位回绕；新输出拒绝使用开始前的旧时间戳。
  没有可用时间戳时由实际提交/播放差值估算，并明确标成 ESTIMATED。
- AudioRecord 适配器使用 MONOTONIC 时间基，但未接入现有真实采集循环。
  实验调用方传入首个采集样本的同一单调时钟时间；不能用配置 buffer 大小代替采样时间。
- 延迟按 `(呈现时刻 - Reverse 调用时刻) + (Capture 调用时刻 - ADC 采样时刻)` 计算，
  校验 0–500 ms 范围；小幅变化平滑，超过 40 ms 的突变失效重置，缺失映射最多沿用估计 100 ms。
  声学 echo 路径延迟与设备队列分开，由 AEC3 自身适应，不再次加到设备排队估计中。
- 参考持续异常 3 tick、时钟持续不可用/播放时连续估算 10 tick、连续 3 tick 超过 5 ms 或
  managed native/链接错误，会退出实验并报告一次明确原因。CPU 检测发生在调用返回后，不能抢占卡死的 JNI。
- `ApmCapturePipeline` 将带处理代次的 10 ms float 输出接到原有 20 ms 增益/gate/Opus 顺序。
  空结果、代次变更、回退或修订均清掉旧半帧和起声，编码前后再核对代次，避免旧结果补发。
  后续接入发送队列仍须使用当前 CaptureVoiceBuffer 的修订校验，在发布点拒绝失效数据。

## 构建复现与来源核验

```sh
python3 tools/build-apm-experiment.py --sdk "$ANDROID_HOME"
./gradlew :audio-opus:connectedDebugAndroidTest -PapmExperimentRoot="$PWD/build/apm-experiment" -Pandroid.testInstrumentationRunnerArguments.class=io.github.ts3mobile.audio.opus.NativeApmExperimentTest
```

Python 3.9+；Meson 1.5.2、Ninja 1.10.2（SDK CMake 3.22.1）、NDK 27.0.12077973、API 26。
`arm64-v8a`、`armeabi-v7a`、`x86`、`x86_64` 均完成静态依赖和 JNI 链接；实际仪器执行为 API 35 ARM64 AVD。
上游发布归档的完整 SHA 锁定内容，不推导未知的 Chromium/WebRTC git revision。
该发行版已经裁剪音频模块并使用 Meson；本项目不执行完整 WebRTC GN 构建、不拉取通话栈，
未打算法补丁，只应用锁定的 Abseil Meson 构建包装。

构建脚本核验四个下载归档，校验解包后 2,206 个源文件的 manifest，禁止未记录的源码缓存修改；
Meson 为 `--wrap-mode=nodownload`，静态 PIC / C++17 / Release，32 位 ARM 不强制 NEON。
可选 JNI 链接指定 16 KB 最大页对齐，独立于默认 ts3opus_jni；没有替换原有 C++ runtime。
llvm-readelf 核验四 ABI 的实验 JNI 所有 LOAD 段对齐均至少 16 KiB；这不替代真实 16 KB 设备验证。
旧 A0 的 40 个指纹中 38 个匹配，仅本轮有意调整的 audio-opus/build.gradle.kts 和 CMakeLists.txt 不同；
旧指纹不重写，现有依赖锁、全部 RNNoise 文件保持一致。

显式实验 Debug AAR 中 strip 后的库大小：

| ABI | APM JNI 字节数 |
| --- | ---: |
| arm64-v8a | 1,071,592 |
| armeabi-v7a | 867,672 |
| x86 | 1,254,944 |
| x86_64 | 1,208,968 |

均低于每 ABI 8 MiB 的原型预算。它们是实验库大小，不代表默认 APK 增量。
默认 Debug/Release APK 的 ZIP 检查均确认不含 `libts3apm_experiment.so`，仍包含原有四种 Opus JNI ABI。

### 固定合成信号结果

AEC3-only：48 kHz，种子 24 的宽带远端信号，回声系数 0.5，16 秒素材；
0–12 秒声学路径延迟 60 ms，12–16 秒为 100 ms，8–12 秒叠加幅值 0.08 的 733 Hz 近端音。
ERLE 取第 6–8 秒和第 14–16 秒输入/输出能量比，双讲幅度取第 10–12 秒。

| 指标 | 结果 |
| --- | --- |
| 60 ms 路径 ERLE | 21.39 dB |
| 变为 100 ms 后 ERLE | 19.76 dB |
| 双讲近端 733 Hz 输出幅值 | 0.07778，输入 0.08，保留约 97.2% |
| APM NS 稳态白噪声衰减 | 14.72 dB；单独 NS，种子 25，第 4 秒统计 |
| AEC3-only 相关滞后 | 430 样本，约 8.96 ms |
| 同条件 AEC3+NS / RNNoise 相关滞后 | 718 / 939 样本，约 14.96 / 19.56 ms，差值 -4.60 ms |
| AEC3-only reverse+capture P95 / P99 | 0.082 / 0.099 ms，模拟器，排除最初 100 tick |
| AEC3+NS reverse+capture P95 / P99 | 0.065 / 0.079 ms，另一近端 fixture，排除最初 10 tick |

相关滞后取稳态宽带片段的最大互相关峰（48 kHz，搜索范围最多 30 ms），
会受非线性抑制与频谱相位影响，是 fixture 的近似相对比较，不是设备传输或端到端时延。
两项 CPU 数据来自不同信号和配置，不能用来断言加 NS 更快；模拟器速度不能替代目标手机实时性门槛。
这些窄范围合成测试不证明真实语音可懂度、双讲保真、蓝牙带宽、源端 SNR 或功耗。

本地忽略目录 `build/audio-a3-2026-10-24/` 保存原生构建、实验/默认门禁、两组 Android XML、
signal-metrics、results、privacy 与 release-identity 日志；来源 manifest 和许可证在 `build/apm-experiment/`。
