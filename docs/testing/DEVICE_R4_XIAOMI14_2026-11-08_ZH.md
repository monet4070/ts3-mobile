远端听感未确认，实机音质验收未完成。用户反馈为“暂不方便判断”。

本轮使用用户授权的手机已保存服务器，进入用户指定成员所在频道。

电脑没有播放测试音频，也没有保存实际采集的 PCM、语音或网络负载。

## 理解、范围与候选

修改前阅读了项目约定、README、架构、贡献指南、R4 记录、后台验收清单，
以及 Activity、麦克风控制／设置、电平反馈和诊断入口。
连接由 app 前台服务维持，protocol 提供会话端口，audio-opus 管理设备路由与采集播放。
本轮沿用既有实现，核对候选与数据后通过实际 UI 操作，补记设备证据。
主要风险是覆盖安装的数据保全、真实频道的短时麦克风发送，以及把客户端状态误当作远端听感。
没有修改生产实现，也没有对超过约 300 行的既有文件进行改动或扩大职责。

## 实测结果

| 场景 | 结果与证据边界 |
| --- | --- |
| 原保存服务器连接 | 一次连接成功，诊断重连为 0、连接失败为 0 |
| 指定频道 | 从用户列表确认目标成员所在频道，再使用实际频道“加入”按钮进入；切换尝试 1、失败 0 |
| 常开采集 | UI 显示“麦克风常开中”和“麦克风已开启 · 正在发送”；Android 记录通信音源 `not silenced`；前台类型为 `0x82` |
| 显式停止 | 设置内“停止麦克风”后显示“麦克风未开启”，前台类型回到仅播放 `0x02` |
| 按住／松开 | 独立 DOWN／UP 输入下，按住时前台类型 `0x82`，松开后 `0x02`；系统有本应用采集事件 |
| 按住时回桌面 | 按住为 `0x82`，Home 后为 `0x02`；回到应用连接保持、按钮恢复“按住说话”，未恢复采集 |
| 音量门控 | 三次 UI 观察均为“门控关闭 · 正在监听”；截图输入约 −95 dBFS；停止采集成功；尚未观察到人声触发开门 |
| 亮屏后台短测 | Home 后约 162 秒，PID 保持；窗口内两次系统检查均未冻结，前台服务存在；约 101 秒间隔的同 UID 网络计数样本收发均增长 |
| 返回应用 | 仍为一次连接、零重连；收到语音帧从 1158 增至 1410，丢弃计数均为 0；稍后可见快照为 1490 帧、麦克风错误 0、最近失败 `NONE` |
| 主动断开 | 先关闭麦克风，再点“断开连接”；UI 未连接，事件有 `EXIT_REQUEST_SENT`、`EXIT_SERVER_CONFIRMED`、`DISCONNECTED` |

网络统计包含 VPN／底层网络的多个计数层，仅用各层正增量证明本应用流量继续，
不将它们相加当作独立语音包数或有效载荷大小。
本次亮屏后台短测不满足清单中的 10 分钟亮屏、30 分钟锁屏或六小时长会话门槛。
未修改 OEM 电池策略、CPU 常醒选项、系统网络或 Doze；采样期间充电，不能据此比较耗电。

第一次自动长按未观察到采集，不计为通过；另一次混合 UI 采样的驱动也未形成有效证明。
随后使用独立 DOWN／UP 与系统前台类型重新验证，并保存原驱动结果和最终结果。
这不构成已复现的生产缺陷，也没有为通过检查修改生产逻辑。

诊断“收到语音帧”只证明协议回调收到帧；UI“正在发送”和系统采集状态也不能证明
对端已经听到清晰音频。零丢弃计数不代表网络零丢包或播放无断续。
−95 dBFS 是单次处理后电平，不能区分当时无说话、声源距离、系统处理和降噪的贡献。
