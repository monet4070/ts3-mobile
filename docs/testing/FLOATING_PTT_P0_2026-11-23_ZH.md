## 历史：同包 QA 候选

`./gradlew -I tools/media-qa.init.gradle :app:assembleRelease` 生成混淆的 `io.github.ts3mobile.app.mediaqa` 测试包，使用开发签名，同时开放只读媒体和桌面单身份 INI 导入。该命令不能用作正式打包。普通构建不继承实验室组件或悬浮窗权限。

- `… → 设置 → 浮动发话实验室`，也可以从测试包的实验室启动图标进入。打开页面不准备悬浮窗、不录音、不发送。已连接情况下只在获同意的隔离频道准备连接测试；无可用音频环境时只验页面和门禁。
- `… → 设置 → 身份与备份 → 导入与恢复 → 导入桌面 TS3 身份（.ini）`。先断开连接；只用可信、专用测试身份，核对预览后才确认更换。不要把 INI 私钥上传到聊天或发给他人。
- 2026-11-24 在 API 35 无音频模拟器覆盖安装同签名旧 QA：设置能打开实验室，桌面导入能打开系统选择器，取消后未提交，QA 未授予录音权限。Debug 的连接前台类型和身份定向回归共 4 项通过；普通 Release 成品无实验组件或悬浮窗权限，身份／媒体开关均为关。未在真机验收连接模式的实际发话。

## 历史：浮窗改版 · 2026-11-24

- **紧凑／展开**：先准备本机或连接测试，再点「回到桌面显示浮窗」。紧凑态约 216 × 56 dp；人数和发言者共用第二行。拖左侧六点手柄，松手吸附到较近一边并保存高度；点同一区域或箭头展开／收起。贴近底部时展开会向上避让，收起回到原位。
- **信息**：两态都在中间区域居中显示当前频道和人数（含自己）。收起时有发言就直接显示一个昵称；展开以发言者为主，显示最多三个昵称和溢出人数，没有发言则显示「暂无发言」。本机态保留采集次数及不保存、不发送说明，不显示虚假频道。浮窗不保存或记录频道名及昵称。
- **麦克风**：右侧是 96 × 48 dp 横向区。「按住说话」可操作，松开即停；其他模式只显示真实状态。展开选择常开或门控即开始采集，选择关闭或切回按住即停止旧采集，不改变主界面设置。门控等待时仍占用麦克风，但不供帧。为避免通知召回自动开麦，浮窗初始为关闭或按住；主界面已有采集需先停。按住 60 秒、常开／门控 5 分钟上限及原有清场逻辑不变。普通 Release 不含浮窗。
- **通知召回**：已连接且无采集、未准备浮窗时，下拉连接通知点「开启浮窗」。权限已配置时，实验室短暂切入，准备通过后返回原任务并显示浮窗；未配置时留在实验室，不自动请求权限。单纯召回不会录音或发话。普通 Release 的连接通知不显示此按钮。
- **参考**：拖动头部、紧凑／展开和发言活动来自 [TS6_Droid_CN 的浮窗实现](https://github.com/YUAXI/TS6_Droid_CN/blob/56d3b4d1991a4c565b1f75f419f4563e772f9614/app/src/main/kotlin/dev/tsdroid/service/FloatingOverlay.kt)，不是先前调研的原仓库；图标、配色、按压和会话门禁使用本项目实现。
- **本轮验证**：API 35 无声模拟器通过拖动、展开／收起、撤权及 20/20 次本机采集与释放；证据在 `build/floating-ptt-probe/7cb12623e46e495fa4be7800ad252413/`。21 项设备测试通过，覆盖常开和门控按选择启动、旧按住令牌无效化、标题居中，以及从系统通知连续两次召回而不录音、不供帧。中文版展示图使用模拟频道和昵称。
- `TS3-Mobile-Combined-QA-PTT-Mode-Driven-20261124.apk` 与旧综合 QA 包同应用 ID、同签名，仍保留桌面身份、媒体及头像功能。只将文件复制到测试机的下载目录并校验 SHA-256，没有自动安装、授权或录音。

## 本机系统资格

宿主关闭音频输入，Pixel 6 配置 arm64 模拟器，应用 target 35。按下时打开真实系统 `AudioRecord`，每次释放后检查 Android 无该应用活动录音；未授权拒绝准备，撤销悬浮许可后去掉悬浮窗和实验服务前台类型。

| Android | 成功打开并释放 | 开启 p50/p95（ms） | 释放 p50/p95（ms） | 本地证据目录（`build/floating-ptt-probe/`） |
| --- | --- | --- | --- | --- |
| 14 / API 34 | 20/20 | 17/45 | 17/28 | `76487342cc524d12aca0114af0104ffa` |
| 15 / API 35 | 20/20 | 19/46 | 18/45 | `f6a5441b503548c6be772eab56fd68a6` |
| 16 / API 36 | 20/20 | 16/50 | 21/27 | `54895fc5071a426a83ee56b2c4959e3a` |

计时只量录音器打开/释放，不量首个有效语音包；三个模拟器的非静音输入均为 0。探针根本不编码、不发包，不把这个 0 当作正式未按压时的发包验收。另在 API 35 的独立运行中，最后一次释放约 5 分钟后观察到 `expired` 和服务销毁。单元测试验证 60 秒硬上限、跨按压令牌、迟到启动失效和释放后重新计时。

复跑：从干净的、已完全开机的模拟器启动 `-no-audio`，安装前保持无 TS3 Mobile，系统语言选择英语；执行 `python3 tools/check-floating-ptt-probe.py --device emulator-5554 --host-audio-disabled`。脚本验证两个 APK 的 Manifest，并写脱敏 JSON。不要把脚本指向真机。

## 连接探针离线结果

同一 target 35 的 Debug 候选，在 API 34/35/36 的只读 arm64 模拟器分别通过 14 项定向测试。两层证据分开记录：

- 已连接服务使用合成会话状态，在可见实验 Activity 内实际提升前台类型，通知显示“已准备 · 未录音”，未启动输入或产生帧；解除准备只留下收听类型。
- 现有麦克风控制器使用 fake 输入，实际语音源连续 20 次各交出一帧合成数据，空闲和释放后均不供帧。旧 `UP` 和本地 `UP` 不结束当次浮窗按压；阻塞中的启动被取消时不供帧，设备未释放不开始下一次。频道失效在异步拆除前先封闭语音源，缺录音许可不准备。假时钟另外验证 5 分钟空闲和 60 秒硬上限。

本地证据在 `build/floating-ptt-connected-2026-11-23/`（APK 摘要、每版日志和 Manifest）。不需要连接实际服务器、有效声源或远端录音；它证明的是采集前台类型与合成帧交付边界，不是 UDP 发送或真实听到发声。

## 一次真机窗口

- 两家厂商各用同一 Debug 变体。先连接隔离测试频道并确认主应用未在采集；所有参与者同意后，打开「浮动发话实验室」，手动授权悬浮窗、麦克风和通知，点「准备连接测试」，切到目标游戏。先测按住，再测选择常开／门控启动、门控等待不发话，以及切到关闭／按住停止采集。不得对真机运行模拟器授权脚本。
- 每机做 20 个独立短句；逐个核对对端听见且未漏首句，松手及间隔无录音指示器、无新增帧。另测切频道、锁屏、撤权、来电、任务移除及回到应用时停止发话；连接未退出时确认仍可收听。记录机型／系统、通过数、首声和释放 p50/p95、失败类别。
- `adb -s <测试机序列号> logcat -d -s TS3_ConnectedPtt:I '*:S'` 只收集实验的按压令牌、持有时长和供应给发送器的帧数；不使用全量日志，不保留音频、身份、地址或协议载荷。语音源供帧不等于 UDP 发包，更不等于对端实听。
- 两厂商实听未通过前，连接 P0 不算通过，正式 P1/P2 不解锁；如失败，继续使用应用内 PTT。
