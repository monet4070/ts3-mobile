# A0/A2 协议边界和实际音频设备：开发验证

2026-11-23 · 基线 `8bd1427` 加工作区改动。默认包仍使用锁定的 `ts3mobile-1`，没有改变传输、编解码、音频缓冲或防外放策略。仅开发验证构建可使用下述带 UDP 探针的固定 fork 源码补丁。

## A0：声明准确的测量边界

- 下行量取 TS3j 的 `DatagramSocket.receive()` 成功返回到语音回调入口；上行量取每帧编码完成到同一非空语音帧的 `DatagramSocket.send()` 成功返回。均用单调 `System.nanoTime()`。成功发送不等于对端接收；结束包、控制包、失败发送无延迟或突发样本。
- 每个采样窗记录两份固定桶直方图及 p50/p95 上界（微秒），另计空读、采集队列逐出和同一连接内的短发包间隔（小于 10 ms）。桶边界由 `voiceTimingUpperBoundsUs` 列出，末桶超过最大界；无样本或分位数落在末桶时，上界为 `null`。锁定的普通依赖缺少 UDP 时间戳，明确显示 `udpTimestampsAvailable=false`，仅空读/逐出仍可用。
- 用标记动作触发即时采样，和实际路由、播放头、欠载及轨道退役落在同一时间线。只导出数字和固定枚举；不保存原始时间戳、帧内容、设备名、端点或凭据。旧采样可继续读取。极端数值触及导出上界时，导出显式标注省略的旧样本数，不删除持久记录。

## A2：显示系统确认的状态

“设置 → 语音播放 → 实际使用的音频设备”分别显示所选输出、获准使用的实际 `AudioTrack` 设备、正在采集的 `AudioRecord` 设备、已知系统静音。A2DP 和 SCO 不合并；其他蓝牙模式没有可靠区分时不猜。未播放、未采集和未知分开，且不会因为开启面板而占用音频资源。诊断追加 `FIRST_WRITE_TO_HEAD_US`，表示首次成功写入到观察到播放头推进，不是耳机出声时刻。
