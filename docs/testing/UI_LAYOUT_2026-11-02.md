# UI layout refinement — 2026-11-02

## Scope and implementation plan

The UI consumes immutable service state through `MainScreen`; connection,
session, chat and voice components already have separate responsibilities.
This change stays in the Compose presentation layer and localized resources.
Protocol, audio processing, persistence and release signing remain unchanged.

- Reduce the connection introduction's height and align the bookmark action
  with the server-details heading.
- Use a compact, single-row session navigation with a distinct chat icon and
  unread badge, while retaining horizontal scrolling for large text.
- Make session search and presence reachable beside the audio route controls.
- Group the growing overflow menu with icons and separators.
- Keep long server names, audio routes and large-text microphone controls
  within their available width, preserving labeled disconnect and PTT release.

All production files in scope are below the preferred 300-line boundary.
`UiFixture.kt` is already 314 lines and owns shared offline test state; it will
not be expanded. New layout regressions belong in a separate test file.
If session header controls grow beyond the boundary, extract their audio/action
row without changing callbacks. Avoid unrelated service decomposition here.

Primary risks are clipping at narrow widths/large font scales, hidden chat
controls when the keyboard opens, and accidental PTT retention when opening a
new shortcut. Verify these with fixture-based Compose tests and device images.

  private connection details.

The physical checks cover the six new layout regressions plus Chinese connection
and session pages, dark palette, 1.8× text on connection/session pages, participant
controls and the overflow menu, and Chinese large-text chat with IME. Captured
and visually inspected these pages, including 320 dp width, the 99+ unread
badge, gate-mode labels, the grouped menu and long server-name ellipsis.

Xiaomi initially blocked some consecutive background test activity launches.
The final phone runner starts the isolated application's main activity before
each individual test; all 13 then pass. The complete 72-test suite runs on the
emulator. This distinguishes the two device results rather than treating a
blocked launch as a UI regression.

The initial new text assertion used `hasVisualOverflow`, which falsely flagged
single-line paragraphs retaining the offered width after text shrank to its
glyphs. The final assertion checks each glyph's horizontal bounds, line count,
ellipsis and height; all six regressions pass on both devices.

Keep the logs, copied unit XML, source SHA-256 manifests, comparison image and
fixture previews under `build/ui-polish-2026-11-02/`. Production/test/configuration
hashes are compared before and after the final device run. The installed debug
APK is copied there as `ts3-mobile-ui-debug.apk`; normal release artifacts keep
the repository's existing application ID and signing configuration.

layout and callback behavior without transmitting messages or capturing voice.
