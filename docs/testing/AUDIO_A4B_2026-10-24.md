# A4b 收包年龄、共享预算与抖动恢复执行记录

## 修改前架构与拆分

OpusAudioPlayer 持有 256 包全局队列，PlaybackStreams 转入每人 TalkerJitterPipeline，
后者混合序号、固定 60 ms 起播、PCM FIFO 与 PLC。转移队列没有统一媒体记账，
worker 停顿后会先解码旧积压。内部 decoder 缺少真实时长与 FEC 查询。
本轮提取 ReceivePolicy、AdaptiveJitterDelay、ReceiveMediaBudget、VoiceReceiveQueue、
ReceivePcmBuffer 与聚合统计；TalkerJitterPipeline 保留调度职责，native 新端口单独放入 opus_receive_jni.cpp。
原整数 FIFO 的溢出测试改由共享预算/带 lease PCM 的独立回归覆盖，避免保留仅供旧测试使用的生产代码。
相关生产文件保持小于约 300 行；不扩大服务/协议职责，既有 public API、发送参数和配置存储不变。

## 设计与风险

全局输入在入队、转入 pipeline 前分别检查 60 ms 驻留年龄。每人所有阶段共享 240 ms 的媒体预算，
同时限制字节与包数；主动丢弃使该说话者的 lease 失效，解码器跳过断层，避免 PLC 补播已丢积压。
自适应目标先为 60 ms，限制 40–120 ms；仅用连续、同长度、非不确定包更新，优先下个 talkspurt 生效。
无真实发送媒体时间戳时不能证明丢包的时长，故 FEC 另需已确认的固定帧长配置；默认 TS3 流不猜测这一条件。
Native metadata 明确查询实际时长与 LBRR；FEC 尝试不是成功统计，实际恢复由含冗余 fixture 验证。
以下参数仍为离线验证后的初始策略，真机听感/时延/功耗不能由模拟轨迹代替。

## 容量、年龄与断层

| 边界 | 初始值与语义 |
| --- | --- |
| 全局输入年龄 | 入队、出队都要求 `now - arrival` 为 0–60 ms；不是网络年龄或采集年龄 |
| 全局输入包数 | 256，独立的内存护栏 |
| 每人媒体 | 11,520 个 48 kHz 样本，即 240 ms；输入/pending/decoded 共用 |
| 每人包数/编码字节 | 96 包 / 122,880 字节（120 KiB），含未完全消费 PCM 的保守编码字节预留 |
| 全局编码字节 | 524,288 字节（512 KiB） |
| 活跃预算/decoder | 最多 64 个说话者；超限淘汰最旧拥有者，避免仅限制输入却无限创建 native decoder |
| 单包 | 最大 61,440 字节；metadata 校验必须成功，实际媒体时长为 2.5–120 ms |

lease 跟随包进入各阶段，读出 PCM 时按样本释放；转到 pending 或解码后不会重新增加容量。
释放操作幂等，失效旧代次的释放不影响新代次。PLC/FEC 的生成样本也必须申请剩余空间，
空间不足时跳过缺口并重置，不能为隐藏数据驱逐已预留的真实下一包。
混音后只有一个 10 ms 输出 tick 的部分写入状态，继续使用 A1 的 100 ms 写入截止；
其实际接受时间纳入 combined wait，而不是把设备缓冲伪装成接收媒体预算。

过龄/过载先使受影响客户端 lease 失效，随后清掉该流 pending/PCM 和 decoder 历史。
同一客户端仍新鲜的队列包会重入新代次，保留最初 arrival，避免旧包过龄时连新包一起永久丢掉。
其他说话者不被一同重置，主动丢弃的积压不会通过 PLC 补回。新代次有效样本内有 5 ms 淡入，
没有复制最后样本、追加 tick 或改变原来的短尾补零行为。
序号展开/去重/旧包拒绝仍在；正常 talkspurt 结束保留已退休序号下界，晚来的旧包不会被当作新起声。
全局最近去重历史也有 64 客户端 / 每人 128 个 ID 的界限。

ReceiveStats 仅保留固定类别计数和最大值，包含过龄、校验失败、预算重置、重复、晚到、PLC、
FEC 尝试、重缓冲，以及 input/talker/combined wait。PlaybackTimeline 在真正接受部分写入时继续更新 combined wait。
没有新增 PCM 存储、身份/地址日志或诊断面板；这些时间不能当作端到端声学时延。

## 自适应策略与保守回退

初始 target 60 ms。仅使用序号连续、到达单调、同媒体时长、非不确定包的间隔偏差，
以最近 64 项的约 P95 计算 `ceil((40 + 2 × deviationP95) / 10) × 10`，限于 40–120 ms。
上升每 16 个有效观察最多 10 ms；连续两次晚到也上升 10 ms；平稳下降需要 128 个有效观察，每次 10 ms。
丢包、乱序/重复、变长边界、断层以及短 DTX/SID 不作为可靠发送间隔训练。
短包 `<=2` 字节保守标记 timingUncertain，结合连续性判断；这不是通用 DTX 检测器。

目标通常在下个 talkspurt 生效。长谈话只有 PCM 空且已知缺口存在时才允许一次 10 ms 重缓冲，
同一缺失序号不重复等待，上限仍为 120 ms。不会为等 FEC 单独延长 deadline，不做时间伸缩或普通样本复制。
`ReceivePolicy(adaptive = false)` 保持固定 60 ms 对照/重建回退，不新增持久用户选项。

## FEC 的启用边界与原生证据

内部端口新增真实包时长查询、LBRR 查询和 decodeFec。metadata 使用 `opus_packet_parse` 校验结构、
`opus_packet_get_nb_samples` 查询时长、`opus_packet_has_lbrr` 确认冗余，损坏包计数后丢弃。
普通解码的样本数还要与 metadata 一致；native 错误不返回无依据的默认 PCM。

**TS3 序号不提供媒体时间戳，也没有远端固定帧长承诺。默认 ReceivePolicy 的 confirmedPacketSamples 为 null，
因此默认 TS3 接收不猜测缺失时长，不自动开启 FEC。** 可验证的内部固定帧长来源可传 480/960，
仅当单缺包、前后帧长匹配、未观察到违背确认的帧型、下一包已到当前播放 deadline 且实际含 LBRR 时尝试。
先恢复前一缺帧，再普通解码下一包一次；无冗余或其他条件不足直接 PLC。
三包/60 ms PLC 上限与“无后继不凭空持续 PLC”保留。
这里只统计 fecAttempts，不把调用数、LBRR presence 或 opus_decode_fec 的隐藏输出称为成功率。

独立合成 fixture：官方 1.6.1，48 kHz mono / 20 ms / VOIP，24 kbps constrained VBR，wideband，
complexity 10，随帧变化的谐波信号；实验组 FEC=2 / loss=30，对照两者为 0。
各 160 包，真实 LBRR 检出为 131 / 0。最初 16 kbps 设置没有产生足够冗余，生成器明确失败；
改用记录的 24 kbps 设置后才形成通过 fixture，未把“开启开关”等同于含 FEC。

Android 对相同丢失位置分别进行 no-loss、FEC 与 PLC 解码，8 个确认冗余的缺帧中，
FEC/PLC 总平方误差比为 **0.0430**（no-loss decode 为参考）。这证明该 fixture 的恢复优于 PLC，
不代表通话质量或任意远端包的恢复率。测试也覆盖无冗余、损坏恢复、连续丢两包，
一次冗余不能恢复两帧，下一包正常解码不重复。生产发送 FEC/loss 参数不变。

## 确定性网络轨迹

Random(28)，每条 10 分钟虚拟时间，20 ms 包；从 65,500 开始覆盖 16 位回绕。
正常每包到达 jitter 0–15 ms；乱序/重复场景 jitter 0–80 ms，每 13 包插入重复。
随机丢包概率为 1/3/5%；突发场景每 100 包丢连续 3 包；worker 暂停发生在第 120 秒。
fake decoder 记录客户端/序号并禁止重复普通解码，所有时钟由测试推进，无 wall-clock sleep。

| 轨迹 | 实际正常解码包数 | PLC 次数 | 最大输入驻留 | 最大 mix 等待 |
| --- | ---: | ---: | ---: | ---: |
| 健康单人 | 30,000 | 0 | 9 ms | 80 ms |
| 1% 丢包 | 29,733 | 267 | 9 ms | 90 ms |
| 3% 丢包 | 29,149 | 851 | 9 ms | 90 ms |
| 5% 丢包 | 28,528 | 1,472 | 9 ms | 90 ms |
| 连丢 3 包 | 29,100 | 900 | 9 ms | 100 ms |
| 乱序/重复 | 29,999 | 1 | 9 ms | 90 ms |
| 8 人 -100 ppm | 每人 30,000 | 0 | <10 ms | 149.956 ms |
| 8 人 +100 ppm | 每人 30,000 | 0 | <10 ms | 89.950 ms |
| 暂停 100 ms | 29,997 | 0 | 59 ms | 90 ms |
| 暂停 500 ms | 29,977 | 0 | 59 ms | 90 ms |
| 暂停 5,000 ms | 29,752 | 0 | 58 ms | 90 ms |

暂停三场景过龄计数为 2/22/247，其他主动无效 PCM 也会丢弃，所以不以过龄计数直接推导全部丢包数。
另有矩阵用例交叉验证单人/8 人、2.5/120 ms 包及上述 3 种暂停，确认恢复后旧包不进入 decoder，
每个仍新鲜说话者均可交付。全局 60 ms 年龄与每人 240 ms 预算在这些轨迹中均满足。
表中 mix 等待只代表应用内模拟，输出实际部分写入等待另有独立 timeline 测试，不能当作真机时延分位数。

Random(29) 的自适应对照为 30 个 talkspurt，每段 100 个 20 ms 包、0–110 ms jitter、相同到达顺序：
固定 60 ms 晚到 **198** 包，自适应 **49** 包。健康网络十分钟对照两者最大 mix wait 均为 **80 ms**，
没有额外 >20 ms 的接收等待。自适应收益仅限这组已记录轨迹，未证明所有网络场景都优于固定策略。

## 剩余验收与 A5

本轮完成离线接收策略与有条件 FEC 能力，未证明未知 TS3 帧长，也未启用发送 FEC。
默认 TS3 的 FEC 保守关闭是未满足前提时的明确路径，不将它计为生产 FEC 已生效。
真实服务器 end-marker 互通、源端校准、非 ARM64 ABI 运行、真实 16 KB 页设备、手机 CPU/热降频、
路由声学/双讲/蓝牙带宽及功耗仍待 A5 验收；APM 的真机采集/时钟/系统效果接入也仍待完成。
下一阶段以已有软件证据为基础安排 A5 的受控设备验收，不以虚拟网络与模拟器速度切换声学默认。
