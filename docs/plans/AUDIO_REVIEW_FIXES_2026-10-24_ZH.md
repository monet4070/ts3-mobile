# 音频审查修复方案

状态：离线修复与质量门禁完成。范围：A0–A4b 审查涉及的稳定性、边界验证、维护性问题；不代替 A5 真机声学验收。结果见[验收记录](../testing/AUDIO_REVIEW_FIXES_2026-10-24.md)。
跨状态复审及后续修复见[补充方案](AUDIO_REVIEW_FOLLOWUP_2026-10-24_ZH.md)与[新验收记录](../testing/AUDIO_REVIEW_FOLLOWUP_2026-10-24_ZH.md)；下表保留首轮设计。

## 架构和兼容性

保留 `app` 服务编排 → `audio-opus` 设备/JNI 和纯 Kotlin 流水线 → `ts3-protocol` 端口的依赖方向。保留默认关闭实验 APM、默认不假定 TS3 固定帧长/FEC 的策略。不改变网络格式、持久化配置或编码参数。已有未提交的聊天、书签和协议工作保持原样。
源代码兼容性：`MicrophoneCapture` 新增带默认空实现的 `invalidateRouting()`，旧适配器可继续编译；生产适配器实现它。`OpusAudioPlayer(Context)` 保留，新增可选输出路由通知构造器与只读播放状态。外部二进制适配器应与本项目一起重新编译。

播放器调度和恢复提取为纯 JVM `PlaybackSession`，Android 类保留线程、焦点回调、设备路由边界。`OpusMicrophoneCapture` 已超过 300 行：本轮先将部分输入组帧/代次处理提取为独立组件，保留设备创建和资源销毁在原类，避免同时重写整个 AudioRecord 适配器。`TeamSpeakService` 等大型服务只做必要接线，后续按服务职责拆分，不在本轮迁移无关功能。
`MicrophoneController` 在加入串行释放后也接近 300 行：发送端口独立提取为 `MicrophoneVoiceSource`；权限与前台服务策略维持原类，后续可独立迁移策略，本轮避免扩大应用层重构。

## 修复顺序和验收

|项|设计|回归/验收|
|---|---|---|
|R1 播放写超时/设备错误|在同一 worker 内丢弃旧代次并关闭旧输出，指数退避后重建；连续失败设上限，输出固定类别诊断。保留旧 worker 未退出禁止新 worker 的保护|零写 100 ms、负返回、工厂失败、恢复后新包可播、耗尽重试、关闭后不得重建|
|R2 停麦阻塞|立即关闭发送端口并清失效数据，阻塞 stop/close 在串行后台执行；快速关开不能穿透旧代次|阻塞 fake stop 时调用线程仍返回，端口不再提供帧；快速关开和销毁|
|R3 采集路由边界|设备偏好变化和实际路由回调推进缓存 revision，清发送/输入残帧/DSP 状态，重新配置平台效果；检查偏好返回值|旧半帧、起声历史、限幅状态不能进入新代次；过时代次 publish 被拒|
|R4 空拍限幅|空拍按实际样本数推进静音 hold/release，不重置到 unity；会话关闭才 reset|空拍与等长静音等效，无瞬间恢复满增益|
|R5 媒体淘汰|按最旧未消费媒体的到达时间选择淘汰者，已消费历史不参与；去重历史单独保留有界策略|老客户端新音频不会因创建时间早被优先丢弃|
|R6 调度/焦点|落后调度设置最小等待，避免持续追赶；拒绝焦点后退避，期间不重复创建 decoder|虚拟时钟长 tick、连续拒绝、恢复焦点、旧包失效|
|R7 FEC 异常|计数，明确丢弃失败补偿块；重置 decoder 后从下一真实包继续并淡入，不对未知状态直接 PLC|fake 解码器先破坏状态再抛错，恢复前必须 reset，真实包只正常解码一次，其他话者不受影响|
|R8 native 生命周期|对 JNI 调用和 close 使用同一实例监视器，关闭幂等；运行时验证并发 close/use|真实 JNI 并发调用只允许成功或已关闭异常，不得崩溃|
|R9 参考缓冲|记录单写者/单消费者/跨线程 invalidation 契约，保留原子代次和有界队列|交错 invalidate 与部分 accepted，不返回混代次块；不凭未证实竞态重构|
|R10 自适应目标|保留 discontinuity 不抹目标行为，集中参数，补异常序列/完整 reset 回归|抬升后 gap 和预算代次切换不意外退回默认|
|R11 显式 FIFO|使用 240 ms 显式容量；超限丢旧块并释放预算/计数|容量内尾部样本正确、超限有界、预算不泄漏|
|R12 常量/死代码|接收/APM 阈值集中为各自配置，删除重复序号适配和仅测试使用的生产常量|现有模拟门禁、直接测试实际序号函数|
|R13 输入错误计数|不静默跳过预算拒绝，计入固定类别指标；保持入口参数校验|异常元数据拒绝可观测，正常 prune 不丢有效包|
|R14 工具脚本|版本读取生产源码选择；SDK/NDK/CMake 从 Gradle 配置读取并显式诊断缺失目录；Release probe 运行时验证版本|Python 单测覆盖非默认版本、缺失/歧义目录；真实 Release APK probe|
|R15 文档|更新计划状态和中文 README 已实现功能清单，记录修复及测试证据|文档与默认/实验状态一致|
|R16 热路径/诊断|元数据解析移出播放器生命周期锁，入队复核代次；RNNoise 临时 vector 改固定 array；会话结束读取脱敏累计计数|准备后的包不重复解析且载荷独立；JNI 合成信号回归；汇总无身份或语音|

## 已纠正的审查意见

普通参考组帧字段并未被采集线程直接读写；native close 实际先置零；CMake CACHE BOOL OFF 有效；起声队列实际丢旧帧；gap 超限不调用完整 pipeline reset；焦点请求受 readyToStart 门控；去重历史不是音频缓存。上述错误描述不作为生产修改依据，相关契约和覆盖缺口按表补齐。

## 门禁和剩余边界

先运行受影响单元测试和格式化，再运行 quality、所有 JVM 测试、Android Lint、Debug/Release 构建、Python 工具回归和隐私扫描。使用项目内 JDK 17/SDK/NDK。Android 离线验证只使用合成 PCM、fake 麦克风和模拟器，不录制真实声音、不连接服务器。硬件 HAL 永久阻塞不能靠 Java 超时强制安全销毁；必须保留禁止重叠 worker 的保护。设备路由、AEC 听感和功耗归 A5。
