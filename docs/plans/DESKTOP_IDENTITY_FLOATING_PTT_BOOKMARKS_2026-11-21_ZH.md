# 下版本执行方案：收藏、桌面身份、浮动 PTT 与音频

2026-11-21 · 待实施。基线：TS3 Mobile 1.2.0（versionCode 16），工作区提交 `8bd1427`。以下版本号、工时和指标均为排期建议，不是已发布功能或实测结果。

**分两次交付。** 建议 1.2.1 只修收藏，避免把旧凭据用于新目标；1.3.0 优先让桌面老用户带着原身份进服，同时验证游戏内按住发话与音频体验。浮窗和立体声各自设发布门槛，未通过时均不阻塞身份导入；不把“回到应用说话”算作浮动 PTT 已完成，也不把立体声当作断音或电音修复。

## 排期与依赖

按一名熟悉项目的 Android 开发者估算，前提是有桌面 TS3、两家厂商真机、耳机及可控测试服。人日为净工程量，不含等待设备、测试者和签名发布。先准备专用测试身份，绝不向用户索取自己的 INI。

| 顺序 | 工单及交付物 | 估算 | 何时可以进入下一步 |
| --- | --- | --- | --- |

| P1 → P2 | 会话和手势所有权 → 浮窗 UI、权限引导及故障回退 | 3–5 人日 | 仅在 P0 通过后执行；未按不采集，失去控制不继续发送 |

原三项及发行约 **10–17 人日**；含上述音频排期约 **16–28 人日**，不含尚未证实需要的专项修复。只有两周时，保收藏热修与身份导入，尽早跑浮窗探针和音频基线，立体声先留开发实验。非本期：多身份列表、按服绑定身份、导出桌面 INI、云同步、耳机／音量键 PTT、锁屏发话、Whisper、重写 TS3j、替换 Opus、双声道上行及无实测依据的默认路由／缓冲改动。

## B1 收藏只把凭据用于用户指定的目标

**现状。** [普通连接表单](../../app/src/main/java/io/github/ts3mobile/app/MainViewModel.kt)改址会清旧密码；[收藏编辑器](../../app/src/main/java/io/github/ts3mobile/app/ui/BookmarkEditor.kt)改主机、端口或手填频道 ID 不完整执行同一隔离原则。频道选择器和清除频道按钮已处理部分情形。[收藏存储](../../app/src/main/java/io/github/ts3mobile/app/bookmarks/ServerBookmark.kt)负责是否保存密码、revision 和数量限制，不负责判断编辑者是否为新目标重新输入了凭据。

| 用户操作 | 服务器密码 | 频道密码及频道选择 |
| --- | --- | --- |
| 改主机或有效端口，含删空、进入非法中间态 | 当场清空 | 当场清空；清旧服的默认频道 ID 与选择令牌，必须在新目标下重选或重填 |
| 只改、清除默认频道（手填、选择器、使用当前频道） | 保留 | 清密码；若通过选择器选新频道，用此次有效令牌替换旧令牌 |
| 改名称、昵称、折叠选项，或目标规范化后不变 | 保留 | 保留；比较规则遵循已有主机 trim／忽略大小写、数字端口和频道 ID；不查 DNS 来猜别名等价 |
| 取消“保存密码”；或 A 改 B 再改回 A | 取消勾选则两种都清空 | 编辑中被清除的秘密不自动复活；取消整个编辑则不修改原收藏 |

**实现。** 在 `app/bookmarks` 建一个纯 Kotlin 编辑草稿变更函数，绑定每个秘密的作用域：服务器为主机＋端口，频道再加频道 ID。所有编辑入口（含大字体的另一套端口字段）走同一函数。变更后用行内提示解释“目标已变更，请重新输入密码”，仅清编辑草稿。保存按最终目标接收用户重新输入的值；不要在存储层无条件比较新旧端点后再次清空新输入。保留现有连接快照校验、过期 revision 拒绝和收藏格式；不迁移或批量抹掉旧收藏。

**回归。** 单测覆盖上表、同名不同端口、无效端口再改回、同数字频道但换服、为新目标重填后保存。Compose 测普通／大字体编辑、手填与选择器；再用 fake 连接入口走“编辑 → 保存 → 重开 → 连接”，断言服务器、频道两类参数均正确，且不依赖真实服务器。附测取消编辑、保存失败、过期选择不覆盖原记录。既有版本无法追溯哪些凭据曾被错用；发布说明提醒曾改址并连接到不受信目标的用户核对收藏，必要时联系管理员更换相关口令。补丁不会撤回历史认证，也不清独立表单。

## I1 和 I2 从桌面导入一个身份

**用户流程。** 设置 → 身份与备份 → **导入桌面 TS3 身份（.ini）**。与“恢复加密备份（.ts3mbak）”分列：INI 含可用于登录的私钥，不要求输入本应用备份口令。引导用户在桌面身份管理器导出，通过自己信任的方式传到手机；不建议发群、贴剪贴板或交给客服。系统文件选择器返回后，显示当前与待导入 UID、偏移、安全等级，以及“原身份权限由服务器按 UID 识别”的说明。只有按下明确的“使用此身份”才写入；完成不自动连接。提示可主动导出新的加密备份，原 INI 由用户自行保管或删除。

1. **先证明互通。** 用官方桌面客户端新建仅供测试的身份，导出单身份 INI，记录桌面版本、系统和预期 UID／安全等级；偏移与文件及手机解析核对。至少覆盖一个 Windows 导出；若声明 macOS 支持，也验一个 macOS 导出。优先由测试运行时生成材料；官方样本用隔离环境的本地 fixture，不提交可用于登录的私钥。CI 使用合成独立向量，不能用同一个库的自导自入替代官方互通证据。
2. **划定读取边界。** `app/identity/documents` 负责 `OpenDocument`、后台读取与关闭；按实际读取字节限 **64 KiB**（与现有材料校验上限一致，读到上限＋1 即拒绝），不信后缀、MIME 或提供方报告的大小。首版支持已用样本验证的单 `[Identity]` 段、唯一 `identity` 值、UTF-8、可选 UTF-8 BOM、CRLF／LF。允许忽略已知桌面显示字段，但不导入昵称或设置；重复关键字段、多身份、未知编码或不支持的变体明确失败。不要把任意外部 INI 原样交给通用解析器；仅从受限结构取本次所需材料，不跟随外部引用。
3. **复用协议校验，不重写密码学。** [Ts3IdentityCodec](../../ts3-protocol/src/main/kotlin/io/github/ts3mobile/protocol/Ts3IdentityCodec.kt) 已经通过固定版本 ts3j 读取 INI，并校验私钥范围、公私钥匹配和偏移。新增纯 JVM 的桌面输入适配，只向现有链路提供规范化、仅含身份的材料；保留 UID 与 offset，不自动生成、修复或提升等级。公开状态仅包含摘要和固定错误类别。私有字节缓冲及时清零，不承诺擦除 JVM 不可变字符串。
4. **共用一次确认与写入。** [IdentityRestoreController](../../app/src/main/java/io/github/ts3mobile/app/identity/IdentityRestoreController.kt) 目前把 picker 和备份口令绑定；明确区分“加密备份”和“桌面文件”两种来源，不用空口令冒充。两条路径产出同一种私有候选，复用预览、单个未完成 picker、代次和清理。通过 `IdentityRepository.replace(material, expectedRevision)` 及 `IdentityUseGate` 提交，不另建存储。相同 UID 和 offset 提示“已是此身份”，不写入、不覆盖回退点；同 UID 但 offset 不同，显示等级差异，下降时默认不替换，禁止静默降级。
5. **维持原恢复语义。** 空库可首次导入，不为展示而生成身份；有效旧身份保留为可验证回退。连接／重连／退出尚未结算时拒绝替换；预览后 revision 变化须刷新并重新确认。取消、旋转或进程重建不能自动提交；提交若已开始，由仓库完成并重新读取权威结果。损坏存储、缺钥按既有错误策略处理，不清库解围。身份页继续禁止截图，不保留 URI 授权，不写明文临时文件，不记录 URI、UID、私钥、口令和原始异常。沿用 [ADR 0031](../decisions/0031-confirmed-identity-restore.md)。

**验收。** 独立单测覆盖已知 UID／offset、错误编码、重复段／键、超长／截断、错误密钥、错选 `.ts3mbak`、读取失败或取消；上述失败断言旧身份与回退点均不变。设备测系统 picker、晚到的回调、旋转、确认中退出、忙碌及 stale revision；同签名升级后验证旧备份仍可恢复。混淆 Release 用专用桌面身份核对 UID，并在隔离测试服验证一项原本已有的权限；再回退到原手机身份核对 UID。记录只留匹配／不匹配和错误类别。

## P0 至 P2 浮动 PTT

**首版承诺。** 默认关闭。用户已连接、选择按住说话、在应用内完成权限和本次准备后，切到游戏可按悬浮按钮向当前频道讲话。未按不打开 `AudioRecord`，不预录；松手或取消立即禁用语音源并停止采集。它不是常开麦克风，不在锁屏、重连中或退出会话后工作，不绕过耳机保护。悬浮窗权限不是录音授权。

### P0 先证明后台第二次也能按住说话

[MicrophoneCapturePolicy](../../app/src/main/java/io/github/ts3mobile/app/service/MicrophoneCapturePolicy.kt) 禁止在应用不可见且采集已停时冷启动采集；[MicrophoneController](../../app/src/main/java/io/github/ts3mobile/app/service/MicrophoneController.kt) 在提升服务类型后还会核对可见性。现有 PTT 在 Activity 暂停时释放。**因此不能把悬浮按钮直接接到已有布尔值，也不能把有浮窗伪装成 Activity 可见。**

- 在独立开发构建验证一种路径：由可见 Activity 内的用户明确操作，在已连接的服务上准备一个**限时、仅本会话有效**的麦克风前台服务类型；空闲不持有录音器，通知标明“浮动按键就绪，未录音”。示例探针用 5 分钟空闲上限；关闭／过期立即解除准备，保留原收听服务。把“已准备”“已采集”“正在发送”分开，检验系统是否允许按下时才采集、松手释放后仍可按第二次。不能借常开采集、虚假通知或全局 `appVisible=true` 过门禁。
- API 34、35、36 在正式 target 下分别验证；至少两家厂商真机覆盖主要版本，其余以模拟器补充。记录首次及后续按压的授权结果、服务类型、实际有效输入、录音指示器、有效语音帧和释放耗时。仅在隔离环境、测试者同意后做短句双端听测；不开远端录音。Android 15 对可见浮窗的条件属于特定后台服务启动例外，不能推导出可随时后台开麦。
- **通过条件：** 已在前台合法准备的会话，切游戏后连续 20 次独立按压均有有效发声，间隔时间不录音、不发语音帧；释放、过期和权限拒绝可观测。若路径违反平台约束、需在空闲录音，或只能靠厂商特权成立，则不采用；没有第二家真机证据则不转正式。失败时收听不中断、用户可回应用操作；不申请无障碍服务，不用循环后台重试。

### P1 服务拥有按压，浮窗只提交手势

| 状态 | 允许的动作 | 退出条件及不变量 |
| --- | --- | --- |
| 关闭／未准备 | 仅前台可发起解释和授权；系统设置返回时重查 `canDrawOverlays` 与录音权限 | 权限拒绝／撤销不代用户重试；原 PTT、通知和收听不变 |
| 本会话就绪 | 在适用的非锁屏前台游戏上显示小按钮；应用内则隐藏 | 无 `AudioRecord`；只持本会话准备资格，不跨切服或进程重建恢复 |
| 合法按下 | 取得“来源＋会话／连接代次＋频道＋本次按压序号”的所有权；服务才可启动现有采集链 | 越代或非当前按钮事件无效；本地页和浮窗不能同时拥有按压；只在实际开始后显示发送中 |
| 释放／取消 | 先关闭语音源，作废该次按压，再异步结算设备释放 | 旧 UP 不影响新按压，迟到的启动回调不得重新开麦；设备未释放或状态不明时禁止下一次启动 |
| 强制停止 | 切服／换频道、重连、锁屏、来电中断、录音／悬浮权限撤回、窗口移除、服务销毁、任务移除或超时 | 隐藏或禁用浮窗，停止并释放；绝不自动续发。另一次会话或解锁后须有新的明确操作 |

服务内新增小型输入仲裁器，对接已有 `MicrophoneController` 和语音源，不新建编码器、音频线程或旁路网络发送。保留 app 内 PTT 的 `onPause` 释放，只释放它拥有的按压；一旦会话或频道失效，全来源停止。对意外丢失 UP 加单次按压硬上限（建议首版 60 秒，持续按住也不自动续期）。权限检查、启动、松手和清理的竞态用假时钟／阻塞 fake 验证。遇系统拒绝、输入被占用或试麦进行中，不显示假“正在说话”；给出回应用处理入口。

### P2 窗口、权限和验收

- `app` 层的私有浮窗宿主只管 `TYPE_APPLICATION_OVERLAY`、触摸、屏幕边界和移除；普通设置只持久化“希望启用”和位置，不持久化已准备／按压状态。仅用户在设置中启用时解释并引导授予 `SYSTEM_ALERT_WINDOW`；首次连接不索取，关闭后提供撤销系统许可的入口。窗口不抢键盘焦点、不覆盖全屏、不显示地址或昵称；应用自己的身份／密码界面、锁屏不显示。系统或游戏禁止覆盖时尊重限制。
- 区分说话和移动，推荐**显式调整位置模式**：拖动位置绝不启动发送；正常按钮支持 DOWN／UP／CANCEL，多指、手势取消、窗口消失均释放。按下与发送用不同视觉状态，配文字／无障碍描述，不仅靠颜色。位置适配横竖屏、刘海和大字体；提供无需瞄准浮窗的小按钮之外的“回应用关闭”。
- Android 测试用 fake 麦克风和合成帧验证，真机再测游戏切换、横屏、Home、锁／解屏、接听来电、切频道、蓝牙断开、系统隐藏悬浮窗、撤权、杀进程、快速交替按压及两次重连。断线前的按压不得在新频道发声；耳机掉线不能借浮窗解除收听保护。检查空闲五分钟以及超时后均无采集。只记事件时间与计数，不采集语音内容。
- **发布判据：** 未按、锁屏、失效会话和释放边界后新产生的有效语音帧均为 0（已交给网络的旧帧不冒称可撤回）；冷启动／销毁后无残留窗口、麦克风或按压状态。记录按下到首个有效帧、松手到录音器释放的 p50／p95，与同机 app 内 PTT 对照；有卡麦、错频道发声、系统拒绝仍显示“发送中”，一票否决。

## A0–A2 定位断音、电音与延迟

沿用 [1.2.0 收听稳定性记录](AUDIO_PLAYBACK_STABILITY_2026-11-20_ZH.md) 的基线。旧包曾在语音包仍持续到达时反复建轨，小米 14 的 A2DP 冷、热启动也有明显差异；这些证据优先支持排查输出，不能给持续电音定因。PocketTS 的对照价值在于较长的轨道复用和清楚地展示实际设备，不照搬阻塞写、持续补静音或混音直接削顶。

- **A0｜测协议边界，不先换协议栈。** 在固定的 TS3j fork 和本地适配层，用同一单调时钟记录「UDP 读取 → 语音回调」和「编码完成 → UDP 发送调用成功」的有界分布与 p50/p95，另计上行空读、采集队列溢出和发包突发。发送调用成功不等于对端收到。先用合成帧和可控局域网验证，不用 JVM 计时器追赶回调作为真机发包证据。若单次故障标记能反复与协议排队或发包突发对上，再在 fork 中单独修对应队列或节拍；没证据就保持传输实现不变。
- **A1｜只改一项的蓝牙 A/B。** 小米 14＋AirPods、固定同一 A2DP 路由、声源、网络、接收档和音量，用现有 `bluetoothStandardOutputExperiment` 比较普通与低延迟输出。先从 `OUTPUT_PERFORMANCE_MODE` 核实实效；实际模式相同的试验不计结论。用有线／USB 作对照，分开测冷启动首句、短句间隙与连续收听，另测按下 PTT 到对端出声。记录声学延迟 p50/p95、漏首句、欠载、重建／退役原因及确切标记时间；写入时刻和播放头不等于耳机出声。如果包稳定但句间仍反复建轨，另开实验延长已确认安全路由的保轨，不与性能模式或缓冲档同时改，也不放松防外放。
- **A2｜把实际状态告诉用户。** 在语音播放设置复用现有服务状态，显示所选与实际输出、实际输入和已知的系统麦克风静音；区分蓝牙媒体与通话路由，不在未采集或状态未知时误报。故障标记用同一时间线关联实际路由、首写至播放头推进、欠载和重建原因。只保留有界的时间、设备类别和计数，不写音频、设备名、服务器地址、凭据或协议载荷；继续使用用户主动导出的离线诊断。

## A3 接收端真立体声

- **范围与开关。** 首版只保留 `Opus Music` 来流自带的左右声道，不做拟立体声；普通语音在立体声输出中等量送往左右耳，麦克风、发包与协议不变。开发开关默认关闭，初期无正式设置。会话使用一个固定输出格式，不因讲话人或单个包的声道变化重建轨道。对未验证、不支持或初始化失败的输出保留单声道回退，不切到扬声器来实现立体声。
- **实现边界。** 在 `audio-opus` 先让 [JNI 解码缓冲](../../audio-opus/src/main/cpp/opus_jni.cpp) 按「每声道帧数 × 声道数」分配、返回，再把声道数传过解码、PCM 队列、混音、写入与播放头计账。48 kHz 下 10 ms 仍是 480 个音频帧，双声道才有 960 个 `Short`；抖动、补帧和过期预算按音频帧计，PCM 容量按实际字节有界。两侧使用同一限幅增益，保留现有单用户增益、静音和路由保护；可选回声参考仍用显式降混的单声道，不把交错数组直接当单声道参考。
- **独立验收。** 扩展 [Opus 兼容素材](../../audio-opus/src/androidTest/java/io/github/ts3mobile/audio/opus/NativeOpusCompatibilityTest.kt)，验证仅左／仅右、单双声道混播、补帧、10/20 ms 与长包、短写和排空、混音不串音、静音后不漏旧帧。先测有线／USB，再测 AirPods A2DP，不承诺 SCO 通话立体声。用 A1 同路由的单声道作为对照；左右可辨、不新增可复现的首句丢失、延迟尾部升高、欠载或重建，且断开耳机不削弱现有防外放保护。未拿到真机证据则保持实验关闭，既不挡其他功能发布，也不宣传“已修复电音”。

## 工程边界与发行检查

- **生产代码与拆分。** 热修限 `app/bookmarks` 和相关 UI；身份限 `ts3-protocol` 的材料适配与 `app/identity`；浮窗限 `app` 的平台宿主、服务与麦克风授权边界，不借浮窗改 `audio-opus` 公共 API／JNI。音频单独交付：A0 限 TS3j fork 与协议适配诊断边界，A1/A3 限输出实验及 `audio-opus` 内部链路，A2 由 `app` 展示已有或新增的只读状态。`TeamSpeakService`（776 行）、`MainActivity`（404 行）、`MicrophoneController`（304 行）不继续堆窗口和手势逻辑：先给旧行为加回归，再抽取单一所有权组件，最后由原入口薄委托，不借机重写已有控制器。
- **配置与兼容。** 收藏与身份不改已发布数据格式、Keystore alias、包名、签名、备份协议或默认音频策略。浮窗探针的权限和入口只进开发构建；若未通过验收，验证正式合并 Manifest 不含该实验权限／组件。验收后才在计划支持的发行构建中声明所需权限，新增本地偏好缺省关闭；服务继续非导出。各正式包及公开体验包独立递增 versionCode。
- **自动门禁。** 按 [贡献指南](../../CONTRIBUTING.md) 配 JDK 17、SDK／NDK；运行 `./gradlew quality :ts3-protocol:test :audio-opus:testDebugUnitTest :app:testDebugUnitTest :audio-opus:lintDebug :app:lintDebug :app:assembleDebug :app:assembleRelease`；再跑 `python3 -m unittest discover -s tools/tests`、仓库隐私扫描与 `git diff --check`。每个行为另建对应 `src/test`／`src/androidTest` 回归。设备用例明确选择隔离设备和测试类；真实录音与服务器测试手动、有同意，不纳入无人值守 CI。
- **升级与回退。** 同签名覆盖测 1.2.0 → 热修 → 功能版，以及 1.2.0 → 功能版；用合成数据核对旧身份、可读收藏、现有 PTT、旧 `.ts3mbak` 和新开关默认值。执行混淆身份探针、升级工具与身份提交中止测试，依 [后台验收清单](../testing/BACKGROUND_VOICE_ACCEPTANCE.md) 记录设备和限制。功能止损采用关闭／移除入口并以更高 versionCode 前向修复，不要求降级、清数据或卸载。身份本地回退不替代外部备份。
- **文档与证据。** 实施时分别更新中英文 README、隐私说明、用户指南、兼容矩阵和 CHANGELOG；涉及身份格式与浮窗采集资格的决策各记 ADR。`docs/testing` 按 B1、I2、P0/P2 和 A0–A3 分别记录提交、APK、系统／机型、通过和未覆盖项。发布负责人按功能逐项签收；探针报告、模拟器通过和真机实听不可互相替代。
