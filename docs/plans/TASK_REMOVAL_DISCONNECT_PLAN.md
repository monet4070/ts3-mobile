**TSM 划掉最近任务后的断开与重连执行方案**

日期：2026-10-13。状态：待实施。本文件是执行计划，不代表代码已修改、测试已通过或服务器配置已调整。

**1. 目标、行为与边界**

本次目标是让用户从最近任务列表划掉 TSM 时，在系统给予执行机会的情况下主动退出 TeamSpeak；重新打开并点击连接时，能够恢复因旧会话残留而被 clones 限制阻挡的连接。

| 用户操作或事件 | 预期行为 |
| --- | --- |
| 按 Home、切换应用、锁屏 | 保持既有后台语音行为，不主动断开 |
| 从最近任务列表划掉 TSM，服务收到任务移除回调 | 立即停止发送语音和自动重连，主动进行协议断开，随后停止服务 |
| 连接过程中划掉任务 | 取消连接并释放握手/socket 资源，不等待建立连接后再退出 |
| 断开确认丢失或网络已不可用 | 到达断开期限后释放本地资源，记录结果，服务器可能仍等待旧会话超时 |
| 系统直接杀进程、厂商清理或强行停止 | 不承诺任何回调执行；重新打开后不自行连接，用户点击连接后才启动恢复 |
| 首次连接收到 too many clones | 显示连接数量限制提示，进行有总时限、可取消的退避重试 |
| 错误密码、封禁、踢出或其他终止性错误 | 保持终止行为，不进入 clones 恢复循环 |

onTaskRemoved() 表示任务被移除，不是专门的手势识别 API。Android 不保证进程终止前必定执行它。成功收到回调、成功发送命令和服务器确认退出是三个不同的结果。

本次先在服务器原有的 clones 限制下验证客户端修复；服务器允许两个 clones 作为后续可选缓冲，不能用于证明退出流程正确。

**2. 当前架构与已核实的缺口**

连接由 app 模块的 TeamSpeakService 承载，ConnectionCoordinator 管理会话、generation、互斥锁及连接状态；ReconnectEngine 管理自动重连。ts3-protocol 模块通过 Ts3SessionClient 和 Ts3jClientSocket 适配实际 ts3j UDP socket。audio-opus 提供音频实现，本次主要复用其现有停止接口。

已核实的代码事实：

- TeamSpeakService 没有 onTaskRemoved()；onStartCommand() 返回 START_NOT_STICKY。
- 服务销毁调用 ConnectionCoordinator.close()，最终调用 socket.close()。实际固定版本 ts3j 的 close() 关闭 DatagramSocket 和执行器，不发送 clientdisconnect。
- 显式断开路径调用 session.disconnect() 后才 close()，但缺少本次要求的短时限与服务器确认结果。
- ts3j disconnect() 包含最多 30 秒的断开状态等待；部分连接状态下还会先等待连接完成。不能在 Android 主线程直接调用，也不能只依赖协程 withTimeout() 限制其运行。
- ConnectionFailure 已将特定 CommandProcessException 中的 too many clones already connected 文本判为可重试，但初次连接失败仍被 coordinator 的首次连接分支终止。
- 现有诊断支持持久化固定事件类别和 Android 11+ 上次进程退出原因，适合扩展，不需要另建日志系统。

ConnectionCoordinator、TeamSpeakService、Ts3jSessionClient 已超过项目建议的 300 行边界。本次只提取新增的断开执行与 clones 恢复策略；会话和 generation 仍由 coordinator 唯一持有。已有 listener、音频及 binder 的进一步拆分继续按 ARCHITECTURE.md 的计划进行，不与本修复混合。

现有 README、README_ZH 及音频探针等未提交变更需要保留。实施前记录基线 diff，后续逐块审核，避免覆盖或混入其他任务。

**3. 第一阶段：建立复现与结果基线**

使用可管理的专用测试服务器和测试身份，先确认该身份的有效 clones 权限及实际拒绝文本/错误类型。配置维持原有限制，避免放宽限制隐藏残留会话。

每次连接成功后从最近任务列表划掉 TSM，立刻重新打开并点击连接。至少重复 10 次，记录以下时间点：任务移除操作、任务移除回调、协议退出请求、服务器确认/用户移除、下一次连接尝试及其结果。

同时设置对照：App 内主动断开、通知断开、按 Home、锁屏和系统强行停止。记录手机型号、Android/厂商系统版本、提交及工作区状态、构建版本、网络条件与诊断结果。至少覆盖问题手机；条件允许时再覆盖接近原生 Android 的设备。

将结果分为：回调到达并确认退出、回调到达但退出未确认、没有回调而进程终止、进程或服务实际仍在运行。现有进程退出原因只能作为辅助证据，不能单独证明用户手势或回调执行情况。

这一步建立后续修复的真实验收闭环。若问题手机不可用，继续完成 JVM 和协议验证，实机结论保持“待验收”。

**4. 第二阶段：实现任务移除后的主动断开**

生命周期入口：

- TeamSpeakService 接入 onTaskRemoved()，只记录固定类别事件并提交退出请求，不进行磁盘同步等待或阻塞网络调用。
- Manifest 明确配置 android:stopWithTask="false"，让服务有机会接收任务移除回调并完成主动停止流程。该配置不保证厂商系统不直接终止进程。
- 不在 Activity.onStop()/onDestroy() 中触发此类退出，避免切后台、锁屏或 Activity 重建中断语音。
- 保留 START_NOT_STICKY，不增加任务移除后的服务复活或隐藏自动连接。

统一退出流程：

1. coordinator 同步登记退出原因和退出所有权，立即使旧会话 generation 失效，禁止旧 listener 和网络回调启动重连。
2. 取消连接、退避、liveness 和稳定连接相关任务，调用现有立即停止麦克风入口，阻止新的音频发送。
3. 若正在握手，关闭正在使用的 socket 以唤醒阻塞连接；不先等待其变为 CONNECTED。部分握手已被服务器接纳但尚未在本地完成的情况归入未确认退出，保留重连兜底。
4. 对已建立的会话，在 IO 执行环境中发送协议 clientdisconnect，并等待属于该 socket/attempt 的服务器退出确认。
5. 使用单调时钟约束整次主动断开，初始目标预算为 2 秒，包含资源接管、发送和确认等待；最终数值依据基线与丢包测试调整。
6. 服务器确认、超时或失败后，均在 finally 中关闭旧 socket、停止旧音频并释放旧会话资源；随后按退出所有权移除通知并停止服务。

底层有界断开：

- 保留现有 disconnect(reason) 签名与 close() 的资源释放含义，不把 close() 全局改成阻塞网络退出。
- 在协议端增加可带时间预算并返回明确结果的断开能力。若采用新增接口方法，提供不执行阻塞 I/O 的 Unsupported 默认实现，保持现有实现的源码兼容；生产适配器必须实现它，现有调用者继续可用。接口说明、fake 迁移与文档同步纳入变更。
- 结果区分 ServerConfirmed、NoActiveSession、TimedOut、Failed、Unsupported；成功清理本地资源不能被写成 ServerConfirmed。
- 在现有 StateAwareTeamspeakClientSocket 适配边界实现受控 clientdisconnect 发送与确认等待，复用 ts3j 的命令编码、加密、序号和可靠传输机制，不手拼 UDP 包。
- 固定版本提供 writePacket() 和带时限的 waitForState()。实现前验证发送、重传、锁等待及等待退出的所有阻塞点；任何本地 watchdog 导致的 DISCONNECTED 都不能被误认为服务器已确认。
- 服务器确认应来自该会话对应的自身退出通知或经过核实的等价协议信号。UDP ACK 单独不能证明服务器已释放用户会话。
- 到期必须中止等待并关闭 socket，验证工作线程真正结束；不能仅让调用协程返回而留下最长 30 秒的后台断开任务。若现有适配边界不能实现这一点，先做受控的最小依赖补丁评估，再进入验收，不宣称已实现短时限。
- 服务 onDestroy() 继续同步释放资源，不在将被取消的 serviceScope 中新建网络退出任务，也不阻塞 Android 主线程等待服务器。

并发与资源所有权：

- 同一会话的通知断开、UI 断开和任务移除合并为一次退出，发送及资源清理幂等。
- 旧退出任务只能操作它捕获的 socket 和音频会话；旧回调不得覆盖新会话状态。
- 用户在退出收尾期间立即重开并连接时，新连接经过同一会话互斥边界排队，最多等待旧流程的剩余预算。新的连接请求必须被保留。
- 旧退出流程在 stopSelf()、通知删除和共享状态更新前校验最新服务请求/generation；不能在新连接已经启动后停止整个服务。需要时让 stopSelfResult(startId) 与 coordinator 的会话所有权校验共同保护，而不是仅比较 socket 引用。

**5. 第三阶段：首次连接的 clones 恢复兜底**

单独定义 clones 错误识别与恢复策略，业务规则保留一个来源。优先使用真实返回中经过核实的结构化错误码；若只能使用当前文本识别，集中处理大小写、包装异常和已观察到的类型，配套 fixture。不得凭推测填写错误码或把所有协议错误变为可重试。

只有用户已经点击连接、当前请求未取消且明确收到 clones 错误时，才允许首次连接进入此恢复流程。正常网络断线继续使用现有 reconnect 行为，错误密码等首次连接行为保持不变。

建议初始策略：1、2、4、8 秒退避，后续间隔上限 8 秒；自首次 clones 错误起总预算 60 秒。这是初始产品参数，不代表服务器一定会在 60 秒内释放旧会话。

恢复要求：

- 单调截止时间覆盖退避和正在执行的握手，不因再次收到 clones、网络切换或其他失败刷新预算。
- 网络不可用时等待可用网络，不空转；总预算仍消耗。正在连接的尝试必须按剩余预算结束，不能在期限之后继续后台连接。
- 每次尝试释放失败 socket，沿用原 Identity，不保存密码或增加新的持久化配置。
- 用户取消、划掉任务或提交新连接立即终止旧恢复；旧尝试的成功回调不得恢复已取消的会话。
- 非 clones 的终止错误立即结束；网络瞬时错误在已经启动的恢复窗口内按既有分类处理，仍受同一截止时间约束。
- UI 使用准确提示：“同一身份的连接数量已达到服务器限制，正在重试”，显示取消入口与重试状态。不能断言另一连接必定是残留会话。
- 预算用尽后显示可操作的失败说明；合法的另一客户端始终在线时应停止，不能无限重试。
- 成功后恢复现有连接后的麦克风资格检查，不绕过 Android 对后台启动录音的限制；恢复不得刷新现有 CPU-awake 总预算。

**6. 诊断、自动化验证与实机验收**

复用 DiagnosticJournal，增加任务移除、主动退出开始、协议请求已发送、服务器确认、退出超时/失败、clones 恢复开始/结束等固定事件类别。只记录时间、固定结果码与不敏感的计数，不写入地址、身份、密码、昵称、异常原文或协议请求。同步更新诊断文档与解析测试。

协议与 coordinator 的回归测试在生产修改前补充：

| 测试层 | 必须验证的真实失败信号 |
| --- | --- |
| 协议适配器 fixture/fake | 已连接时发送一次正确退出请求；服务器确认、丢确认、发送失败和未连接结果不同；到期终止实际阻塞任务并释放资源 |
| 退出确认与 generation | 本地关闭/watchdog 不能冒充服务器确认；过期或不同 socket 的通知不能完成新会话退出 |
| coordinator JVM | 先禁止重连和发送音频，再协议退出，最后清理；重复请求幂等；握手中退出可终止；旧退出不能 stopSelf 新连接 |
| clones 恢复 JVM | 首次 clones 后恢复成功；真实长期并行登录到期失败；退避及握手共用截止时间；离线、取消、新请求和终止错误不会刷新或绕过预算 |
| 诊断与 UI 文本 | 新事件可往返解析且无敏感内容；中英文状态、取消和到期提示一致 |
| Android/服务器实测 | 系统真实触发回调、手机实际停止发送、服务器实际释放会话、立即重连结果；JVM fake 不能证明这些事实 |

实机至少执行以下矩阵：

- 正常网络下划掉后立刻重连，问题手机连续 20 次；每次记录回调、退出确认、服务器离线时间和下一次连接结果。
- 连续传音时划掉，验证麦克风和发送及时停止，通知和服务退出。
- 握手中、退避中和网络切换时划掉，验证无后台复连和残留本地工作线程。
- 划掉后在退出窗口内立即打开并提交连接，验证旧流程不停止新会话。
- 丢弃退出请求或确认、断网划掉、系统强行停止，验证“未确认退出”报告准确；恢复网络并由用户发起连接后，clones 能恢复或到期失败。
- 同一 Identity 的另一个真实客户端持续在线，验证到期停止，不踢掉该客户端。
- 按 Home、切应用、锁屏，以及 UI/通知主动断开，验证既有行为没有回归。

初始验收目标：正常可用网络下，从任务移除回调到收到服务器退出确认不超过 2 秒；问题手机正常网络矩阵连续 20 次完成确认退出并可立即重连。超过该目标时报告分布、原因和未覆盖条件，不能仅以日志里出现“请求已发送”判为成功。没有收到回调的强杀场景单独评价恢复能力，不计作主动退出成功。

**7. 变更清单、实施顺序和交付判定**

生产代码：TeamSpeakService、ConnectionCoordinator、新增聚焦的退出控制器与 clones 策略、ReconnectEngine 的必要接入、Ts3SessionClient/Ts3jClientSocket/Ts3jSessionClient、诊断事件与 UI 消息映射。audio-opus 生产代码预期无需修改。

测试：扩展协议 socket/session、ConnectionCoordinator、generation 和诊断的独立测试；新增退出控制器与 clones 策略测试。实机步骤独立记录，不将其等同于 JVM 测试。

配置：仅 app Manifest 的 stopWithTask 明确配置。首轮不改服务器权限、依赖版本、身份格式或密码保存方式；如果有界断开需要依赖补丁，独立记录其理由、兼容性和验证。

文档：新增相关 ADR，说明划掉任务代表主动退出的产品决策、有界断开和恢复边界；同步 ARCHITECTURE、README 中英文、BACKGROUND_VOICE_ACCEPTANCE 与诊断事件说明；保护现有未提交内容。

实施顺序：基线复现 → 协议有界断开及回归 → 任务移除接入及并发回归 → 首次 clones 恢复及回归 → 全部门禁 → 原服务器限制下实机验收 → 可选服务器缓冲。

可选服务器缓冲：在客户端验收后，针对测试用户评估 i_client_max_clones=2，确认有效权限并记录改前改后结果及回滚值。该设置会允许同一身份同时登录两份客户端，连续快速强杀仍可能占满。暂不依赖自动踢旧会话的脚本；如后续实施，必须有经过验证的身份与设备授权，保护合法的另一个客户端，管理凭据只留在服务器侧。
