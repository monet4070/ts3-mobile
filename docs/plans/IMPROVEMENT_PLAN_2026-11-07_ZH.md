# TS3 Mobile 使用体验与工程质量提升计划

日期：2026-11-07（Asia/Shanghai）

代码基线：`main` / `7a1e36e`；当前应用版本 `1.0.0` / `versionCode 14`。

状态：规划完成，实施待开始。本文不是新版本验收记录，也不表示其中功能已经实现。

## 1. 目标与计划边界

这次提升围绕四个用户结果：

1. **日常操作顺手**：读聊天不丢位置，默认频道按名字选择，后台私信有提醒。
2. **音频调得准、记得住**：参数跨服务重建保留，门控有电平反馈，操作一个人的音量尽量不打断其他人。
3. **长期使用有保障**：身份能够经过验证地备份、迁移和恢复，升级不破坏已有数据。
4. **改动容易验证和交接**：测试覆盖真实入口与组合路径，变更能单独回滚，重复实现逐步收敛。

本轮用户要求编写详细提升计划。本文安排后续工作，不直接修改生产代码、发布应用、连接真实服务器或发送消息。历史 ADR 中关于范围的限制按当时日期保留；新行为实施时新增或更新相应决策记录，不把旧记录改写成已经批准或完成的新功能。

继续保持单活动服务器、三模块结构、现有协议与音频边界。没有具体收益的依赖升级、音频算法替换、聊天历史数据库、云同步、多服务器并发和全局状态框架不纳入本计划。

### 1.1 现有架构与改动落点

| 层 | 当前责任 | 本计划主要改动 |
| --- | --- | --- |
| `app` 界面与应用层 | Compose、前台服务、权限、会话编排、存储、通知 | 阅读位置、设置持久化、频道选择、私信通知、身份管理界面 |
| `ts3-protocol` | 纯 JVM 协议模型、身份编解码、会话端口与适配 | 身份验证所需的最小端口；其余功能优先复用既有接口 |
| `audio-opus` | JNI、采集与播放、路由、增益、门控和缓冲 | 低频电平反馈、单人静音与全局播放失效的边界 |
| 测试与构建 | JVM fixture、Compose、JNI/设备测试、CI | 入口到结果的回归、CI 纳入关键 UI 路径、分层验收 |

`TeamSpeakService` 仍持有会话与音频组件；界面读取不可变状态并提交操作。新通知逻辑不进入协议层，参数存储不进入音频层，音频线程不直接更新 Compose 或写入磁盘。

### 1.2 审查结论的证据等级

| 发现 | 当前证据 | 计划处理 |

## 4. 阶段 A：补齐日常使用流程

### A1：跨页签保留聊天阅读位置

**用户结果**：读到一半去看频道或用户，再回来仍在原处；有新消息时保留阅读位置并显示跳转入口。

涉及：[ConnectedPanel](../../app/src/main/java/io/github/ts3mobile/app/ui/ConnectedPanel.kt)、[ChatConversationContent](../../app/src/main/java/io/github/ts3mobile/app/ui/ChatConversationContent.kt)、[ChatPanel](../../app/src/main/java/io/github/ts3mobile/app/ui/ChatPanel.kt)。

实施顺序：

1. 用 30 条以上、含多行内容的 fixture 复现“聊天 → 频道 → 聊天”和“聊天 → 用户 → 聊天”。记录首个可见消息标识及偏移，先验证现有实现是否失败。
2. 将必要的保存容器提升到跨页签持续存在的会话界面；避免靠同时挂载所有页面保留状态，否则隐藏聊天页可能继续执行可见性／已读逻辑。
3. 保存会话选择、滚动锚点、偏移和跟随最新消息的意图。聊天正文、草稿、UID 继续由服务内存持有，不写入 saved state。
4. 页面状态与当前手动会话绑定。普通重连保留；主动断开、切换服务器、关闭私聊时清理。进程重建后无法证明是同一会话时不恢复旧桶，不能只凭可能复用的数字 ID 认定有效。
5. 如果复现不成立，保留能证明行为的测试并更新审查结论，不为实现猜想而移动状态。

验收：

- [ ] 跨两个主页面往返后，原消息仍可见，滚动偏移在布局允许范围内保持。
- [ ] 离开聊天时收到新消息，回来不会自动吞掉未读或跳到尾部。
- [ ] 切换私聊、旋转／状态恢复、重连仍保留各自位置。
- [ ] 消息因有界保留被移除时，安全回退到仍存在的锚点，不崩溃、不串会话。
- [ ] 关闭会话和切服后，不恢复上一会话的选择与位置。

预计新增独立的跨页签回归文件；复用现有 `ChatPanelTest`、`PrivateChatPanelTest` 的 fixture。测试名称与文件名在实施时确定。

### A2：保存麦克风调音参数

**用户结果**：上次调好的输入音量、降噪、AEC 意愿和门控阈值，下次仍然有效。

涉及：[MicrophoneSettings](../../audio-opus/src/main/java/io/github/ts3mobile/audio/opus/MicrophoneSettings.kt)、[MicrophoneController](../../app/src/main/java/io/github/ts3mobile/app/service/MicrophoneController.kt)、[TeamSpeakServiceState](../../app/src/main/java/io/github/ts3mobile/app/service/TeamSpeakServiceState.kt)、[设置界面](../../app/src/main/java/io/github/ts3mobile/app/ui/MicrophoneSettingsDialog.kt)。

设计与边界：

- 在 `app/settings` 增加一个专用、版本化的偏好存储。只有非敏感调音值，优先复用现有 DataStore 依赖，不强行复用服务器表单加密格式。
- 保存四个用户选择；不保存“正在采集”、PTT 按下、自动发送状态或实际 AEC 可用性。服务新建仍从 PTT 开始，加载参数不会调用开始采集。
- 读取在 IO 完成，实际参数应用经过现有采集串行控制。晚到读取不能覆盖用户刚刚修改的值；用户交互优先。
- 滑杆即时影响当前采集，磁盘保存合并频繁修改并在交互结束时提交最新值，不在每个采样回调或主线程执行存储。
- 缺字段使用已定义默认值；损坏、未知版本或读写失败给出可见状态，不静默把未知格式覆盖为空。明确恢复默认操作及其保存失败行为。
- 保持服务内存中的新参数可用，但写入失败时不能显示为“已保存”。设置说明从“仅服务内有效”更新为真实行为。

验收：

- [ ] 四项参数写入、服务销毁重建和进程重启后正确恢复。
- [ ] 旧安装没有新偏好文件时，行为与当前默认值一致。
- [ ] 延迟读取、快速连续修改、写入失败和未知版本不会错误回写或覆盖用户编辑。
- [ ] 加载参数、打开设置、恢复默认都不会自动请求录音或开始发送。
- [ ] 当前录音期间调整参数仍满足旧有采集代次、队列和 DSP 连续性测试。

更新 ADR-0016 的后续决策、双语用户指南与架构说明。格式作为新独立偏好增加，不迁移身份、表单和收藏数据。

### A3：按名称选择默认频道，并支持当前频道收藏

**用户结果**：用户可以通过当前频道或频道名称配置收藏，无需自行取得内部编号。

涉及：[BookmarkEditor](../../app/src/main/java/io/github/ts3mobile/app/ui/BookmarkEditor.kt)、[BookmarkDialogs](../../app/src/main/java/io/github/ts3mobile/app/ui/BookmarkDialogs.kt)、[ServerBookmark](../../app/src/main/java/io/github/ts3mobile/app/bookmarks/ServerBookmark.kt)、[频道列表](../../app/src/main/java/io/github/ts3mobile/app/ui/ChannelPanel.kt)。

第一步交付：

1. 已连接时增加“保存当前服务器为收藏”，明确可同时使用当前频道。
2. 编辑与当前服务器端点匹配的收藏时，提供按名称／层级选择频道，以及“使用当前频道”。同名频道用路径区分。
3. 内部继续保存原有 `defaultChannelId`，避免无必要的数据迁移；数字输入放在高级设置，支持离线编辑已有条目。
4. 新建收藏从实际活动连接上下文取值，不能从可能已经改过的连接表单推断当前服务器。按现有端点归一化规则匹配，不通过 DNS 解析猜测两个地址是否是同一服务器。
5. 提交时重新检查手动会话、端点、频道仍存在及收藏 revision。若上下文已变则保留编辑并说明原因，不把旧服务器频道写到新收藏。
6. 密码仍由用户明确选择保存，不从当前连接或表单偷偷带入。只增加名称选择，不改变加入权限与密码校验。

第二步小交付：在频道行提供可见的“加入”操作或菜单动作，继续保留双击快捷方式；窄屏、大字体和 TalkBack 均能完成加入。复用已有加入入口与密码弹窗，不新增一套加入逻辑。

验收：

- [ ] 从当前频道保存收藏，断开后通过收藏连接能够请求原频道。
- [ ] 同名频道、密码频道、已删除频道和无权限加入均有明确结果。
- [ ] 编辑另一个服务器的收藏时，不展示当前服务器频道作为可保存目标。
- [ ] 打开编辑器后断线、切服或条目被更新，不发生跨服务器／旧 revision 覆盖。
- [ ] 未选记住密码时，新增入口不会持久化密码；现有收藏格式仍能读取。
- [ ] 可见加入入口通过键盘／无障碍操作可用，双击旧路径不退化。

当前频道自动滚动定位可作为后续小项，不要求本项同时重做频道树折叠规则。

### A4：后台私信通知与点击定位

**用户结果**：锁屏或使用其他应用时知道有人私信；点击提醒后看到正确会话，而不是误定位到复用 ID 的其他人。

涉及：[ChatState](../../app/src/main/java/io/github/ts3mobile/app/chat/ChatState.kt)、[ChatStore](../../app/src/main/java/io/github/ts3mobile/app/chat/ChatStore.kt)、[PokeAlertObserver](../../app/src/main/java/io/github/ts3mobile/app/service/PokeAlertObserver.kt)、[PokeNotifications](../../app/src/main/java/io/github/ts3mobile/app/service/PokeNotifications.kt)、[MainActivity](../../app/src/main/java/io/github/ts3mobile/app/MainActivity.kt)。

设计与边界：

- 新增独立的私信通知频道与观察逻辑，沿用戳一下的前后台判定经验；不混用通知 ID 或改变戳一下行为。
- 只处理新接收的普通私信。发送回显、频道消息、戳一下、仅未读计数变化、连接快照重放不应制造新私信提醒。
- 第一版默认通用文案，不包含正文、昵称、服务器、UID。是否展示预览留待后续独立选择。
- 多条私信使用汇总提醒；初始建议 2 秒合并窗口，避免连续声音。窗口是可测试策略参数，实测后再调整。
- 通知点击使用不含个人信息的临时定位 token，由活动服务解析到当前会话；在打开页面前验证会话仍有效。不能只传裸 client ID 或可跨服务重建复用的数字。
- 处理 Activity 已在栈中与冷启动两个入口，以及服务尚未绑定时的待处理定位。过期 token 只打开应用，不自动连接、不恢复已清空消息、不选择错误会话。
- 点击通知本身不等于消息已读；仍由实际可见消息范围更新 readThrough。
- 通知权限拒绝、系统频道关闭、勿扰时，应用内未读继续正常；提供系统设置入口，不循环弹权限请求。

验收：

- [ ] 新私信后台到达时提醒，前台不重复打扰；已有未读切到后台不会补响一遍。
- [ ] 连续消息按规则合并；草稿编辑、主动发送、重连和戳一下不触发重复私信通知。
- [ ] 已有 Activity 与新 Activity 均能定位有效会话，等待绑定期间不会丢失点击意图。
- [ ] 断开、切服、进程重建、会话关闭、client ID 复用后，旧通知不能打开错误对象。
- [ ] 真正显示消息后才清理对应未读；其他会话未读保留。
- [ ] 拒绝权限和禁用通知频道时不崩溃，不影响收发；锁屏内容与 Intent 不含敏感数据。

自动化使用合成事件与通知构建检查。真实设备的锁屏声音、系统限制单独验收；不需要为离线测试给真实用户发私信。

### A5：输入电平、门限线与状态反馈

**用户结果**：用户说话时能看见电平是否超过门限，知道门控为何打开或关闭。

涉及：[MicrophoneFrameProcessor](../../audio-opus/src/main/java/io/github/ts3mobile/audio/opus/MicrophoneFrameProcessor.kt)、[VolumeGate](../../audio-opus/src/main/java/io/github/ts3mobile/audio/opus/VolumeGate.kt)、[MicrophoneCapture](../../audio-opus/src/main/java/io/github/ts3mobile/audio/opus/MicrophoneCapture.kt)、麦克风服务状态与设置界面。

设计与边界：

- 展示与门控判定一致位置的电平，即降噪和增益处理后的信号。明确标签，避免把它称为硬件麦克风的原始音量。
- 增加阈值线及“低于门限／起声判定／发送中”等可解释反馈；不把低电平直接判成设备故障。
- 音频线程只更新小型数值快照，初始最多 10 次／秒向应用层发布最新值，不阻塞采集，不为每个采样块创建协程。
- 打开设置本身不开始采集。没有采集时显示“麦克风未开启”；PTT 用户可在正常按住讲话时观察。
- 不保存 PCM、电平轨迹或声纹信息。停止、权限变化或采集代次失效时清空旧读数。
- 增加可访问的文字摘要，屏幕阅读器不随每一帧播报。

验收：

- [ ] 合成静音、轻声与高电平输入对应合理读数，门控比较使用同一测量定义。
- [ ] 修改增益或阈值后，指示与实际门控行为一致；保持现有起声和收尾规则。
- [ ] 停止／重启／切路由后不显示上一代采集值。
- [ ] 发布频率有上限，订阅取消后不保留 UI 回调；CPU、分配和采集连续性相对基线无明显退化。
- [ ] 设备实测确认显示延迟可用于调节，文字与颜色在浅深色、大字体下清楚。

本项不包含自动校准或本地回放试音。它们需要另行设计采集资格、发送隔离与反馈回路，不能在加电平条时顺带引入。

## 5. Q1：把完整使用路径纳入自动门禁

现有 CI 已启动模拟器，但应用仪器测试只选跑少数类。优先复用现有工具和 fixture，避免为覆盖率数字引入新测试框架。

- [ ] 首先纳入 A1 的跨页签回归及已有聊天、私聊、收藏核心操作。
- [ ] A2–A5 各自落地时，将对应的参数恢复、定位、权限和 UI 回归加入门禁。
- [ ] 初期可运行已有相关测试类；若耗时超出现有 CI 预算，再分离稳定、无截图输出的关键流程套件。完整布局／截图检查继续按 UI 改动执行。
- [ ] JVM 和 Android 测试结果及失败日志作为 CI 产物保留，名称对应源提交；敏感内容不进入上传产物。
- [ ] 新代码失败时不以反复重试到通过替代定位。明确区分模拟器启动故障与断言失败。
- [ ] 不删除现有音频生命周期、Release 身份和编解码探针以腾出时间；必要时根据测量拆作独立 CI job。

验收不看新增多少测试文件，而看是否能阻止以下回归：切页丢阅读位置、晚到读取覆盖设置、收藏跨服务器写入、旧通知定位错误、单人静音误清其他流、调度停顿导致媒体持续欠消费。

## 6. 阶段 B：专项优化单人静音

### B1：缩小失效范围，同时保留静音生效保证

**用户结果**：静音 A 或调整 A 到零音量时，B 的连续讲话尽量保持；解除静音不会播放 A 的旧队列。

涉及：[OpusAudioPlayer](../../audio-opus/src/main/java/io/github/ts3mobile/audio/opus/OpusAudioPlayer.kt)、[PlaybackSession](../../audio-opus/src/main/java/io/github/ts3mobile/audio/opus/PlaybackSession.kt)、[PlaybackStreams](../../audio-opus/src/main/java/io/github/ts3mobile/audio/opus/PlaybackStreams.kt)、[PlaybackTimeline](../../audio-opus/src/main/java/io/github/ts3mobile/audio/opus/PlaybackTimeline.kt)。

当前全局失效保护了已混合但尚未完整写入的音频。不能简单删除 `invalidate()`，也不能把“没有全局重置”当作正确性的全部标准。

实施顺序：

1. 通过真实控制入口构造 A、B 双流，记录对 A 静音前后 B 的 decoder 生命周期、排队 PCM、输出提交及全局 reset 次数。保留单流和焦点／路由失效对照。
2. 区分三个边界：A 尚未混音的媒体、已经混合的待写块、已经交给系统的音频。只对前两者建立应用可保证的行为；已提交硬件缓冲及正在执行的 native write 无法承诺瞬时撤回。
3. A 的队列与解码状态按参与者失效。已混合待写音频通过受控输出代次或 worker 命令失效；保留 B 尚未混入输出的解码和缓冲状态。
4. 优先保持输出实例；若硬件 flush／重建确有必要，仍保留不相关的接收状态，测量其代价。不通过无限缓存或延迟静音来掩盖断点。
5. 焦点丢失、全局静音、路由安全保护、停止／重连仍保留完整失效边界。所有 session/timeline 状态由既有 worker 串行修改。
6. 若不能在合理复杂度下同时满足静音语义与连续性，保留当前实现并记录失败方案与测量，不提交不完整的“优化”。

自动验收：

- [ ] 通过 `replaceParticipantGains` 的完整路径验证，不能只调用 `PlaybackStreams` 内部方法证明单人隔离。
- [ ] 静音 A 不销毁 B 的 decoder，不丢弃 B 尚未混音的有效队列，不触发无理由的共享预算重置。
- [ ] 切换边界之后不开始提交含 A 的旧代次待写块；解除静音不回放 A 的过期包。
- [ ] fake output 支持部分写入、零写入、阻塞与异常，验证并发静音、路由变更和停止不会串代次。
- [ ] B 的损失仅限确实必须丢弃的已混合／设备输出边界，能够统计并解释；不额外清空其接收缓冲。
- [ ] 旧播放节拍、负包龄、接收预算和十分钟模拟测试继续通过；不增加延迟上限来换取表面连续。

设备验收：同一路由和输入条件，对比 B 连续讲话时反复静音 A 的声音缺口、输出重建与异常计数。覆盖扬声器／有线及可用蓝牙路由；无法测试的路由标为未验证。离线模拟不能单独支持“听感已解决”的发布声明。

本项独立提交与发布候选，不同时升级 Opus、RNNoise、APM 或重构协调器。

## 7. 阶段 C：身份可恢复与存储实现收敛

### C0：统一加密封装，保持旧数据可读

涉及：[IdentityVault](../../app/src/main/java/io/github/ts3mobile/app/identity/IdentityVault.kt)、[ConnectionSettingsVault](../../app/src/main/java/io/github/ts3mobile/app/settings/ConnectionSettingsVault.kt)、[BookmarkVault](../../app/src/main/java/io/github/ts3mobile/app/bookmarks/BookmarkVault.kt)。

- 提取小型 AES-GCM 封装和 Keystore 密钥访问组件；三个 Vault 继续拥有各自序列化、事务与错误处理。
- 保留现有独立 key alias、DataStore 名称、字段名、版本标记和密文布局。本项不主动重加密、不合并数据文件。
- 区分创建新数据时允许生成密钥与读取已有密文时密钥缺失的情况；后者报告不可解密，不假装获得了有效旧密钥。
- 所有加密／解密工作保持在适当 IO 边界，错误不输出密钥、明文或密文内容。

验收：合成旧格式密文与相同测试密钥在新实现中可读取；新写入仍符合旧格式；验证错误密钥、损坏标签、缺失密钥、未知版本均不会清空原存储。Android Keystore 往返、现有收藏并发更新、连接表单保存与 Release 身份探针继续通过。

### C1：先确定身份文件兼容范围和恢复方案

当前 [Ts3IdentityCodec](../../ts3-protocol/src/main/kotlin/io/github/ts3mobile/protocol/Ts3IdentityCodec.kt) 的生成／解码能力来自固定版本 ts3j，但不能仅凭存在 `read/export` 就宣称兼容所有桌面客户端的身份导出格式。

C1 必须交付：

- [ ] 使用新生成的合成身份验证现有格式，记录导入后 UID 是否保持；不提交真实私钥或个人身份文件。
- [ ] 建立格式清单：当前编码格式、拟支持的桌面格式、明确不支持的格式及错误提示。
- [ ] 明确第一版只管理一个活动身份，替换必须在断开状态完成，不实现身份多开。
- [ ] 设计可跨设备解密的备份容器，记录版本、算法、KDF 参数、盐、nonce、认证及大小／资源限制。使用成熟密码学实现，不能直接导出仅由本机 Keystore 加密的内部 blob 作为迁移包。
- [ ] 明确备份口令丢失无法恢复，以及系统文件选择器目标位置由用户选择；对暂存文件和异常清理制定规则。
- [ ] 设计“验证新身份 → 保留可回退旧身份 → 原子替换 → 核对结果”的顺序及回退入口。

只有格式往返与失败场景验证通过后，才进入 C2；设计发现的未知格式不能靠容错解析猜测身份。

### C2：身份导出、导入、替换与恢复

用户流程：

1. 身份管理页面说明身份与昵称的区别，显示适合核对的身份标识及备份状态；不显示私钥。
2. 导出由用户选择文件位置并设置／确认备份保护信息。文件写入成功并完成可解密校验后才报告成功；失败不标记为已备份。
3. 导入先在有界内存中验证格式、解密、身份与 UID；显示将替换的对象与影响，明确确认后写入。
4. 替换只在完全断开、没有握手／退出任务占用身份时允许。导入或取消不自动连接服务器。
5. 旧身份保留一份受保护的本地回退副本，直至新身份存储与读取验证完成，并按明确策略处理其保留／清理；不能要求用户为失败恢复而清空应用数据。

验收：

- [ ] 合成身份导出后在全新安装的独立测试存储中恢复，UID 一致；同设备往返不足以证明跨设备可恢复。
- [ ] 错口令、损坏文件、超大输入、非法 KDF 参数、不支持版本、取消选择均不改变当前身份。
- [ ] 替换途中进程结束／写入失败后，至少有一个经过验证的身份可读取，且恢复路径明确。
- [ ] 保持现有服务身份使用与安全等级信息的兼容，协议公开接口若有必要新增，记录源／二进制兼容边界。
- [ ] 文件选择器、备份与导入流程不把敏感内容写到剪贴板、日志、通知、诊断或自动备份。
- [ ] 在真实 minified Release 中验证解析与恢复；旧版覆盖升级后原身份、表单和收藏仍可读取。

更新身份相关 ADR、安装升级说明、隐私说明、用户指南与兼容性矩阵。第一版支持哪些桌面格式，以验证结果为准，不提前承诺。

## 8. 阶段 D：可独立安排的完善与重构

### D1：提供主题选择

复用现有浅／深色配色和预览，增加“浅色／深色／跟随系统”。旧安装没有设置时仍保持原先明确选择的暖色浅色默认，不静默改变视觉偏好；用户可以主动选择跟随系统。

主题偏好可与 A2 共用同一个应用偏好存储入口，但保留独立字段、职责和测试，不扩展成通用配置框架。验证切换不重建服务、不改变 PTT／采集状态；检查系统栏、菜单、弹窗、IME、大字体及状态恢复。应用语言选择暂不与主题捆绑。

### D2：将连接活性监测从协调器提取

优先提取网络状态代次、静默传输检查与监测定时任务。`ConnectionCoordinator` 继续唯一持有会话替换、请求所有权和退出决策；监测组件只产生绑定当前会话的结果，不自行关闭 socket 或开始连接。

先补能证明当前行为的可控时钟／fake 会话回归，再机械迁移逻辑；保持既有时间参数与重连分类。测试旧监测晚到、网络反复切换、离线等待、终态拒绝、任务移除与新连接竞争。事件监听器是否继续拆出，在这一步完成后重新评估，不一次提取全部职责。

成功标准是理解和测试活性监测不再需要掌握整个协调器，并且没有新增多余的 Host 转发层。文件行数仅用于提示评审，不是验收目标。

## 9. 测试、文档和发布门禁

### 9.1 每个交付的完成定义

一个工作项只有同时满足以下条件，才能从“实现中”变为“完成”：

- 生产路径接通，错误、取消、并发替换、旧数据兼容按该项要求处理。
- Bug 有独立回归；新行为有对应测试。先验证坏路径可失败，再检查修正后通过，避免仅测试内部 helper。
- 适用格式、Lint、编译／类型检查、单元与集成检查通过。Kotlin 类型验证由模块编译／构建承担，不另称不存在的独立 typecheck 命令。
- UI 项检查中英文、窄屏、大字体、键盘和无障碍；音频／系统通知另有适用设备记录。
- 文档与隐私说明反映实际行为；新偏好有默认值、范围、生命周期和升级说明。
- 提交能独立审查，验证结果绑定该提交；未覆盖事项和回滚方式明确。

### 9.2 建议验证命令

以 [CONTRIBUTING](../../CONTRIBUTING.md) 和当前 Gradle 配置为准。小改动先跑相关模块，合并／候选版前补完整适用门禁。格式修复与检查顺序执行，不在并行 Gradle 中同时跑 format 和 check。

```sh
./gradlew quality :ts3-protocol:test :audio-opus:testDebugUnitTest :app:testDebugUnitTest --max-workers=2
./gradlew :audio-opus:lintDebug :app:lintDebug :app:lintRelease :app:assembleDebug :app:assembleRelease --max-workers=2
pwsh -NoProfile -File tools/check-repository-privacy.ps1
git diff --check
```

正式验收需要新执行的 JVM 结果时，单独运行并保留任务结果：

```sh
./gradlew --no-daemon --max-workers=2 --no-build-cache --rerun-tasks quality :ts3-protocol:test :audio-opus:testDebugUnitTest :app:testDebugUnitTest
```

UI 相关变更可运行完整应用仪器套件，也可按当前改动选择已有测试类后，在候选版前补完整适用套件：

```sh
./gradlew :app:connectedDebugAndroidTest --max-workers=2
```

音频仪器套件包含 opt-in 录音／实验探针，不能无差别当作无人值守回归。B1 使用 CONTRIBUTING 列出的离线播放、路由、JNI、生命周期类；按实际改动补其他相关用例。

身份、依赖或 R8 相关变更运行 `tools/check-release-identity.ps1`；音频编解码／JNI 相关变更补 `tools/check-release-codec.py` 等适用探针，设备 serial 与 SDK 路径从当次环境取得。

### 9.3 分层证明，避免把测试数量当成用户结果

| 层级 | 能证明什么 | 不能替代什么 |
| --- | --- | --- |
| JVM fixture | 状态、并发顺序、预算、时钟、输入输出样本关系 | Android HAL、实际声音、OEM 后台行为 |
| Compose／Android 仪器 | 页面操作、状态生命周期、权限入口、Keystore 与 JNI | 所有尺寸机型、锁屏提示体验、物理蓝牙 |
| Minified Release 探针 | 实际优化产物中的关键解析、JNI／反射路径 | 完整使用流程与生产签名升级 |
| 实体设备 | 指定设备／系统／路由下的音频和系统行为 | 未测试设备的普遍保证 |
| 覆盖升级与恢复 | 指定旧版到新候选版的数据和签名兼容 | 任意历史版本与未知身份格式 |

测试记录至少包含源 SHA、命令、执行／缓存情况、成功失败项、设备条件、产物摘要和剩余风险。真实地址、身份、密码、消息与音频不得作为公开测试产物。

### 9.4 提交与发布方式

- 每个编号原则上一个独立 PR；较大项拆成可解释的子交付。例如 A4 可分通知策略／系统接线，B1 可分复现／实现，C2 可分备份／导入恢复。
- 一个 PR 不同时包含音频算法升级、协调器重构和用户功能。避免再次把多个阶段汇入无法分开回滚的大提交。
- 分支使用 `codex/` 前缀；此文档不会创建分支、提交、推送或 PR。
- 第一轮体验功能可作为下一次功能版本候选，具体版本号在候选切出时确定；独立修复可另发补丁版。每个正式 APK 使用递增 `versionCode` 与明确的版本／标签，不把历史特殊重发当成常规流程。
- 发布使用既有签名、精确源提交和审核过的 APK；安装验证使用同签名覆盖，不用卸载重装来证明升级成功。

### 9.5 回滚边界

| 改动 | 回滚策略 |
| --- | --- |
| 页面状态、频道入口、主题 | 单独回退代码；不触碰身份与现有收藏格式 |
| 新偏好 | 旧版本忽略新增存储；不在降级时删除新偏好。升级重新读取需维持版本兼容 |
| 通知 | 停止生成并清理本应用对应通知；系统通知频道关闭／删除的处理单独说明 |
| 单人静音优化 | 回退到当前保守的全局失效实现，保留复现测试与已知限制记录 |
| 加密封装重构 | 保持旧格式和 alias，代码回退后已有密文仍可读取 |
| 身份替换 | APK 回退不会自动恢复旧身份，必须依靠独立验证过的身份回退流程；文件失败不得破坏现有身份 |

Android 正常安装通常不允许降低 `versionCode`。面向用户回滚应以递增版本重新发布已知实现，不能要求用户清空数据降级。

## 10. 从历史弯路中保留的执行规则

1. **先判断故障能否由客户端恢复，再设计恢复引擎。** clone-limit 保持终态提示；普通网络恢复沿用现有分类。没有新的协议依据，不恢复旧自动克隆限制重试。
2. **验证真实调度与组合路径。** 播放链路要经过节拍器、接收队列和输出；界面要经过页签切换、生命周期和服务状态，不能只证明内部组件正确。
3. **测到的收益决定是否保留优化。** B1 如只减少 reset 计数却留下旧音频或引入更多延迟，不算成功；A5 的显示必须与实际门控一致。
4. **成熟的功能要完成最后一步。** 收藏不仅能存 ID，还应方便选择；聊天不仅能接收，还应及时通知；调音不仅能修改，还应能理解和恢复。
5. **简化以减少维护点为目标。** 优先收敛真实重复的密码学实现；不为了达成行数目标制造更多共享状态和转发接口。
