## GitHub 发布执行步骤

以下步骤在本表冻结之后执行，结果由 GitHub tag/Release 和分发的 `BUILDINFO.json`
共同记录；不在尚未执行时预先勾选。

1. 最新 PR CI 通过后按正常流程合入；对照 434 个构建输入，确认后续差异仅为文档。
2. tag 指向合入提交，BUILDINFO 分别保留实际 `sourceCommit` 和 `releaseCommit`。
3. 创建草稿并上传签名 APK、`SHA256SUMS.txt`、`BUILDINFO.json`；正文使用中英双语。
4. 在新目录重新下载草稿，复核摘要、包名、版本、签名与源码关系。
5. 公开为非 prerelease 的 Latest，核对 `/releases/latest`，重新下载公共资产并安装冒烟。
6. 出现阻断问题时说明影响，调整 Latest/预发布或撤下问题资产，发更高 versionCode 的修复；
   不静默替换同版本 APK，不引导无备份用户卸载降级。
